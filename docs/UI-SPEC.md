# 终端操作

Logox 使用 React/Ink 的全屏界面。正式模式需要 stdin 和 stdout 都连接到交互式终端；不同终端对鼠标、修饰键和剪贴板的支持可能不同。启动与命令见[使用指南](USAGE.md)。界面的代码结构见[模块总览](modules/README.md)和 [TUI 路标](../src/tui/AGENTS.md)。

## 对话与角色窗口

主窗口显示 Logox 的回复和角色任务卡。每个角色都有独立窗口、输入草稿和阅读位置；在主窗口使用 `@actor` 派发不会自动切换窗口。自定义角色复用相同交互。

角色卡收起时显示任务与状态，展开后可查看目标、报告、实际模型和执行过程。角色结束后更新原卡片，不追加一份重复报告。Thinking 与工具调用使用内联卡片，各自保留状态和耗时；失败、拒绝和取消会明确显示。

时间线按“发言轮”组织：一个说话人的一轮（Logox 从一条用户消息到下一条用户消息；角色在自己窗口里的一轮同理）只显示一次名字，其间的角色卡、工具组、思考和叙述都不再重复。标题行在导轨两列里画说话人的符号（用户 `❯`、Logox `◈`、角色各自的符号，粗体、说话人颜色），其余行是与背景混合后的安静 `│ `，导轨始终正好两列。轮仍在进行时，标题名字后显示实时动态：旋转点阵、当前动作（`Thinking`、运行中的工具标题、`Waiting on Kalon`）和耗时；本轮结束后不再显示。运行中的角色卡副标题优先取该角色最新的 `⏵` 叙述。

一轮里所有的思考合并成标题正下方的一行：`▸ Thought 6 times · 1m 18s · 1,032 tokens`（只有一次时为 `Thought for 7s · 12 tokens`），运行中显示 `Thinking` 和实时耗时；展开后每次思考一段，左列是该次耗时，正文为次要色斜体；整个思考正文只有一个展开行，按跨所有思考的行数统计（`… N more lines`，默认 12 行），点击后就地展开并在正文末尾变成 `… show less`，再点收回。角色卡展开后，这一行是卡内第一行。

背景色只表示“已展开”：折叠的行和卡片没有背景；展开的工具、思考、角色卡使用所属角色色混入背景的淡染，按嵌套深度分级（深度 1 约 6%、深度 2 约 11%、深度 3 约 16%），所以子块与父块始终可以区分：展开的角色卡是深度 1，其中的工具卡或工具组是深度 2，展开的工具组里的工具是深度 3；Logox 自己的工具卡和工具组用 Logox 色按同样的规则（顶层深度 1）。淡染恰好覆盖该卡片的区块，不再画 `▄` / `▀` 封边。展开后的标题行以 `▾` 开头、文字为正常前景色，正文向内缩进两列，占满可用宽度并自然折行（没有 100 列上限）。连续折叠的角色卡紧凑排列、中间不留空行，正文与第一张卡之间留一行。步骤方块 `▮` 保留：运行中标题为前景色并带流光，完成为灰色方块加次要色标题，失败为红色方块加红色原因（只出现一次，没有尾随的 `Error` 标签；权限拒绝在原因前保留红色 `Denied`）。

命中区域：折叠的卡片或行只在实际文字范围内可交互（不含导轨，不含尾部空格），悬停时方块、` · ` 分隔点和标题一起变为发起该动作的角色色（Logox 自己的工具用 Logox 色，Kalon 卡里的工具用 Kalon 色）。展开的卡片整块淡染区域都是命中区域：点击标题文字或卡片里任何空白淡染处都会收起；嵌套行、展开行、链接、`■ Stop` 等交互子元素保留各自的动作。所有卡片类型（工具、工具组、思考、角色卡、Task 简报）行为一致，键盘（Enter / Ctrl+N / Ctrl+O）路径不变。

耗时与状态位置统一：耗时永远以淡色 ` · 1.8s` 紧跟在内容之后，不在行中间、不靠右；一行的最右端留给运行状态，与角色卡相同：运行中的可单独取消的工具（目前是 Shell）在最右端显示可点击的 `■ Stop`（点击或 Tab 聚焦后 Enter 只终止这一次调用，不结束所属角色的步骤），点击后变为 `Stopping…`；完成的工具右端什么都没有（没有 `Completed`）。其余工具（Read、Grep、Glob、Edit、Write、WebFetch、MCP、浏览器、Automa）没有单独取消的通道，因此不显示 Stop。标题过长时用 `…` 在行宽内截断而不是折成第二行，摘要和耗时保留。工作区内的路径显示为相对 cwd 的路径，区外保持绝对路径。

所有工具共用同一种卡片结构。标题行：折叠为 `▮` 加次要色标题，展开为 `▾` 加正常前景色标题，耗时以淡色紧跟在内容后；标题后仅在能补充标题没有的信息时才带一段摘要（`lines 1–200 of 312`、淡色 `added 16 · removed 16`（为 0 的一侧省略）、`7 matches in 3 files`、仅在非零时出现的红色 `exit 1`、`new file · 112 lines`），自明的工具不带摘要；成功是安静的（Shell 退出码 0 不显示任何摘要）。正文向内缩进两列，显示的是渲染后的用户视图，而不是给模型看的原始结果文本：

- 默认最多显示 12 行，超出时只有一个展开行 `… N more lines`（Edit 在 hunk 边界截断时为 `… N more hunks`），斜体淡色；悬停时变亮并加下划线，点击或键盘（Ctrl+N 选中、Ctrl+O）就地展开正文，展开后展开行变为正文末尾的 `… show less`（同样的斜体淡色与悬停效果），点击收回 12 行上限。Shell 显示输出尾部，开关行始终位于尾部上方。开关行只有文字本身可点，旁边的空白淡染处仍然收起整张卡片。
- 空结果不会什么都不画：一行斜体淡色提示，如 `No output`、`No matches`、`No files matched`、`Empty file`，摘要里不重复。
- 链接、URL 和域名始终带下划线（`link` 色）。
- Read：右对齐淡色行号加轻量语法着色（注释淡色，字符串、关键字、数字取主题的 `syntax*` 色），`.md` 走 Markdown 渲染；图片是不可展开的一行 `image · 1280 × 720 · 84 KB`。
- Edit：淡色行号栏、`−` / `+` 与淡红 / 淡绿底色，hunk 之间用淡色 `⋯` 行分隔。Write：新文件显示开头若干行并标 `new file · N lines`；覆盖已有文件且知道旧内容时显示差异。
- Grep：命中按文件分组（路径用 `path` 色，后跟淡色命中数），每条命中是行号加正文，命中的子串以暖色（`highlight`）加粗；Glob：目录部分淡色、文件名用 `path` 色。
- Shell：第一行 `$ 命令`（命令用 `path` 色），然后是输出尾部，stderr 与疑似错误行用错误色。
- 阶段标题：模型在文本首行写的 `⏵ 子目标` 是阶段。随后的工具组以它为标题（正常前景色），淡色动词摘要跟在后面，如 `▸ 调整配色 · Read 4 files · Ran 2 commands · 12.7s`；没有阶段时回到动词列表。只有一次调用时，有阶段的组也成为单成员组，意图不会丢；阶段之后是不可折叠的工具（Edit、Write 等）时，阶段单独占一行（角色符号加意图），不再在组上方重复一行。Logox 自己的一轮、角色卡和角色自己的窗口规则相同，实时动态和角色卡副标题都使用当前阶段。`⏵` 标记本身不会出现在屏幕上，存储的消息保留这一行，由时间线剥离。
- 工具组展开后，每个成员是自己的折叠行（`▮` 加标题与摘要），可各自展开，结构与上面相同。
- WebFetch：标题 `WebFetch(域名)`，不带摘要；正文第一行是完整 URL（`link` 色加下划线，域名加粗），第二行是页面标题（加粗）加淡色 `状态 · 大小`，随后是页面内容的 Markdown 渲染摘录；原始 HTML 永远不会直接显示。
- 浏览器（Playwright）：同一角色连续的页面动作合并为一张 `Browser` 卡，摘要 `N actions`，不与 Read / Grep / Shell 混在一起。展开后每个动作一行平实的话，各有自己的 `▮`：`Opened <URL>`、`Clicked "元素"`、`Typed "文字" into 元素`、`Pressed 键`、`Screenshot W × H → 路径`（路径用 `path` 色）、`Snapshot of 页面`、`Console · N errors`（有错误时标记变红，摘要里淡色显示第一条错误）、`Evaluated 代码`、`Waited for "文字"`、`Closed browser`。有可看内容的动作（控制台、求值结果、快照摘录）可单独展开，其余是不可展开的一行。
- 其他 MCP 工具与未知工具：标题 `mcp · 服务 › 工具`；正文先是对齐的 `键  值` 参数行（键淡色、值正常前景，嵌套对象为单行紧凑 JSON），再是渲染后的结果（像 Markdown 时按 Markdown 渲染），同样受 12 行上限约束，空结果为 `No output`。敏感字段遮蔽只作用于显示，原始账本不变。
- SendMessage：`SendMessage to <符号 名字>`（名字用目标角色色）加摘要 `ask · awaiting reply` / `ask · answered` / `inform` / `reply`；展开为 `Q  问题`、`A  回答`（标签淡色）。对方回复后，提问方的卡片更新为 `answered` 并显示 Q 与 A；回复方的卡片总是先显示原问题 Q 再显示自己的 A，不会只剩一个孤立的回答。角色之间的对话不出现在 Logox 主时间线，除非发送方或接收方是 Logox；各角色自己的窗口仍显示自己发出的消息。
- AskUserQuestion：回答之后是一份记录：摘要 `answered`（或 `cancelled`），每个问题一行 `Q  问题`，所选答案 `A  答案` 以用户色加粗，备注用次要色。交互选择面板本身不变。
- 隐藏工具（Actor、ListActors、ReadActor、LoadTools、UpdateTaskProgress、_FinishRound、_GitStatus）成功时什么都不画，也不会出现在工具组摘要里；失败时只有一行：红色 `▮`、次要色标题（如 `Actor(kalon)`）、` · `、红色原因，耗时紧随其后。浏览器与 MCP 的失败也走同一个失败视图：原因是一行干净文字（不显示 `### Error` 之类的 Markdown 标题）。角色卡本身不受影响。CancelActor 是不可展开的一行 `■ Stopped <符号 名字>`，用该角色的颜色。
- Automa 的任务行使用同样的正文结构：12 行上限、同一个 `… N more lines` 展开行、同一种空状态。

点击卡片折叠或展开，双击角色卡进入其窗口。拖选优先于点击，选择文字不会停止任务。停止按钮只作用于对应任务，停止 Logox 不会连带取消所有角色。

审批和提问显示在所属任务内。新请求会自动展开一次，之后可以手动折叠；稍后回答不会丢失请求，主输入仍可编辑。界面只提交回答，是否执行由运行时权限检查决定。

## 快捷键

### 输入与发送

| 操作 | 按键 |
|---|---|
| 排队发送（Queue），不打断正在运行的任务 | Enter |
| 补充给所选运行中任务（Steer），不取消任务 | Ctrl+T |
| 换行 | Shift+Enter、Alt+Enter 或 Ctrl+J |
| 光标在输入内上下移动；到首行 / 末行后浏览更早 / 更近的输入（无命令候选时） | ↑ / ↓ |
| 扩展选区 | Shift+方向键、Shift+Home/End；Ctrl+Shift+Home/End 选到草稿首尾 |
| 全选、复制、剪切 | Ctrl+A、Ctrl+C、Ctrl+X |
| 词跳 | Ctrl+←/→ 或 Alt+←/→ |
| 删除当前视觉行前部 / 后部 / 前一个词 | Ctrl+U / Ctrl+K / Ctrl+W |
| 移到当前视觉行行首 / 行尾 | Home / End |
| 移到草稿开头 / 结尾 | Ctrl+Home / Ctrl+End |
| 展开全屏草稿编辑 | 点击输入栏右侧 `⛶`（见下文） |

输入框从一行增长到最多五行，超出后滚动输入视口。折叠与全屏模式共用草稿、光标和选区；鼠标可跨行拖选，Backspace / Delete 删除选区，键入或粘贴替换选区，中文组合字和 emoji 按完整字形处理。输入区不填充背景，保留终端自身的透明效果；只给选中的文字绘制高亮底色。文字使用主题的 `composerFg`。上下两条分隔线取当前窗口角色色按 45% 混入背景后的低对比色，首行以 `❯ `（角色色 90% 混入背景）作提示符，续行用两个空格对齐；光标、换行、鼠标命中都按这两列前缀计算。全屏编辑器不加前缀。不添加占位提示。

输入历史按会话和角色窗口隔离，只收录已接受的人类输入，不收录派工书、同伴来信、提问回答或登录密钥。恢复会话时可浏览账本中保留的人类输入；当前进程内成功提交的命令也可找回。浏览到最新一条后再按 ↓，返回浏览前的未发送草稿和光标位置。多行草稿先按视觉行移动，到边界才切换历史；Shift+↑/↓ 始终扩展选区。命令候选打开时 ↑/↓ 仍用于选择候选。

Queue 与 Steer 是两种操作。Steer 需要明确的目标：用 Ctrl+N 或点击卡片选中某个活动，页脚会标出目标；窗口里只有一个运行中任务且未显式选择时，Ctrl+T 直接作用于它。所选任务已结束时草稿会保留，不会改发给别的任务。Steer 不能用于 `/` 命令或 `@actor` 派发，这类输入请用 Enter 排队。

### 停止、复制与退出

| 操作 | 按键 |
|---|---|
| 停止主窗口里 Logox 的当前循环 | Esc（先关闭菜单、清除选区、回到主窗口，之后才停止） |
| 复制选区 | Ctrl+C |
| 无选区时退出 | 1.5 秒内连续按两次 Ctrl+C |
| 立即退出 | Ctrl+D |

复制不计入退出次数。Ctrl+C 不会停止任务；停止用 Esc 或卡片上的停止按钮。

主窗口 Esc 停止 Logox 后，若输入框为空，将被停止任务对应的最近一次人类输入放回输入框，供修改后重发；已有新草稿时不覆盖，可用 ↑ 找回先前输入。不会自动重发、撤销已完成的工具或停止其他角色，也不会把内部报告当成用户请求恢复。菜单、输入选区、问题焦点、角色窗口和全屏编辑仍优先处理自己的 Esc。

用户主动停止会明确告诉模型，避免它盲目重试。卡片上的 `■ Stop` 只终止那一次 Shell：卡片以柔和（非错误红）颜色显示 `Stopped by user`，并保留已输出的尾部内容；模型收到 `Stopped by user.` 开头的结果，附带部分输出，并被告知不要自行重跑。Esc 停止整个回合时，被打断的工具结果写明“用户在工具完成前中断”，账本末尾追加一条隐藏的 `[Interrupted by user]` 提示（不进入时间线，回合卡片已经显示 Interrupted），模型下一轮先读用户的新消息：有新指示就照做，否则先核对当前状态并询问再恢复；回合记忆标记为 `Interrupted by user`。Director 通过 CancelActor 停止角色时，该角色的账本写入 `Stopped by Director` 及 Director 给出的理由，与用户中断区分开；崩溃恢复、关闭退出的措辞不变。

## 全屏草稿编辑

普通输入栏右侧有一个 `⛶` 展开图标，悬停时变亮。点击后，当前角色的同一份草稿和光标展开为整屏编辑，不会产生第二份副本。多行粘贴直接进入可编辑文本；软折行不会改写提交的原文。

| 全屏内操作 | 按键或入口 |
|---|---|
| 插入换行，不发送 | Enter、Shift+Enter、Alt+Enter、Ctrl+J |
| 按 Queue 语义发送并收起 | Ctrl+Enter 或右下角 Send |
| 补充给所选运行中任务 | Ctrl+T |
| 收起并保留草稿、光标与时间线阅读位置 | 右上角 Collapse；Esc（有选区时先清除选区，再按一次收起） |
| 移动、扩展选区 | 方向键、Home/End、Ctrl+Home/End、PageUp/PageDown；按住 Shift 扩选 |
| 词跳 | Ctrl+←/→ 或 Alt+←/→ |
| 删除当前视觉行前部 / 后部 / 前一个词 | Ctrl+U / Ctrl+K / Ctrl+W |
| 全选、复制、剪切 | Ctrl+A、Ctrl+C、Ctrl+X |
| 缩进 | Tab 插入四个空格 |
| 退出应用 | Ctrl+D；无选区时 Ctrl+C 仍遵循二次退出规则 |

鼠标可以点击定位、拖动选择；滚轮可独立浏览长草稿，继续输入或用键盘移动后光标重新被跟随。全屏编辑不用于登录密钥或工具提问的回答，也不改变角色归属、权限或任务执行。发送失败时草稿保留，返回普通输入栏显示错误。

| 时间线 | 滚轮 | 每次滚动三行，保留阅读位置 |
| 时间线 | 单击卡片 | 折叠或展开 |
| 时间线 | 双击角色卡 | 进入该角色的窗口 |
| 时间线 | 拖选 | 选择文字，拖到视口边缘会继续滚动；优先于折叠 |
| 卡片上的停止按钮 | 单击 | 停止对应任务 |
| 输入栏 | 单击 | 把光标放到点击位置 |
| 输入栏右侧 `⛶` | 单击 | 展开全屏草稿编辑 |
| 命令候选与面板 | 单击 / 滚轮 | 聚焦并选择 / 滚动列表 |
| 状态栏 Actor 胶囊 | 悬停 | 胶囊以角色主题色反色高亮 |
| 状态栏 Actor 胶囊 | 单击 | 定位到主时间线上该角色最新的任务卡片并高亮；如果当前在角色窗口，先回到主窗口 |
| 状态栏 Actor 胶囊 | 双击 | 直接进入该角色的独立窗口 |
| 状态栏文字 | 拖选 | 选择状态栏可见文字，松开后写入剪贴板；不含 ANSI 与右侧 Actor 胶囊 |
| 状态栏空白处 | 单击（位于角色窗口时） | 回到主窗口 |

运行中的 Actor 胶囊靠右排列，按激活顺序用 Starship 咬合链条连接。

## 阅读与复制

回复支持标题、列表、引用、代码、链接和表格。窄终端会折行，或把表格转为纵向字段显示。用户输入与工具原文按字面显示。

滚轮和翻页保留阅读锚点，回到底部（Ctrl+E）后恢复跟随。复制的是当前显示的文本：保留真实换行，连接软折行，并包含可见的表格框线，不还原原始 Markdown 标记；原始内容仍保存在账本中。复制通过 OSC 52 写入终端剪贴板，终端需要支持。

## 模型与命令面板

输入 `/` 打开命令候选，用法见上文“命令候选”。面板只保留上下横线，输入区上方的候选只保留上横线；选中项与描述使用主题的 `accent` 高亮，不跟随角色颜色，未选中描述用灰色。

模型选择器标题为 `Select Model for <角色>`，由供应商标签页、`Search:` 搜索框、该供应商的模型列表和思考档位组成：

| 操作 | 按键 |
|---|---|
| 切换供应商标签页 | Tab / Shift+Tab |
| 搜索 | 直接键入；Ctrl+U 清空搜索框 |
| 移动选择 | ↑ / ↓，翻页用 PageUp / PageDown |
| 确认 | Enter |
| 关闭 | Esc |
| 删除所选的可删除项（如自定义模型） | Ctrl+X |

标签页与搜索只影响当前供应商的列表；档位只显示当前模型支持的选项。短屏优先保留可选模型。打开选择器本身不会启动模型任务。

查询类命令（`/skills`、`/models`、`/help`、`/commands` 等）使用只读结果面板：用 ↑↓、PageUp/PageDown、Home/End 或滚轮阅读；Ctrl+C 复制原始全文，不取消任务也不退出；Esc 返回并保留输入草稿与阅读位置；Ctrl+D 仍可退出。

模型和思考档位的切换直接反映在状态栏，不追加时间线回执；设置保存只在页脚短暂提示。局部错误留在当前表单，必要的全局错误保留摘要与可展开详情。

`/settings` 包含 Settings 与 Statusbar 两个标签，用 Tab / Shift+Tab 或鼠标切换。Settings 标签的三项顺序固定：

| 项目 | 操作 |
|---|---|
| Theme preset | ←/→ 或 Space 切换，列出所有已加载主题 |
| Cursor style | ←/→ 或 Space 切换（Block、Underline、Bar） |
| UI animations and motion waves | ← 关闭，→ 开启，Space 翻转 |

↑↓ 移动焦点；Enter 只应用当前标签并留在页面，另一个标签的草稿不会丢；Esc 关闭并丢弃尚未应用的修改。保存中键盘与鼠标暂时锁定，失败时保留草稿与错误，可重试。`/animations` 是 `/settings` 的旧别名；`/statusbar` 直接打开同一个编辑器，Enter 保存后收起。

`/config` 是只读的 Effective Configuration 页，显示当前生效的模型、思考档位、Base URL、Automa 和执行限制，不编辑配置。可编辑的偏好在 `/settings`，运行状态与用量在 `/status`。

所有开关与单选、多选控件使用 `[ ]`（未选）和 `[■]`（已选）。聚焦行使用主题 `accent`，已选但未聚焦为白色，未选且未聚焦为灰色，禁用项为灰色。`❯` 只表示键盘焦点，移动焦点不会自动勾选多选项。

## 提问面板

所有提问（工具提问、权限、`/login` 表单）共用同一面板，只保留上下横线。分类与题号在上横线，宽屏显示 `Question 2/3`，空间不足时收为 `2/3`。终端变矮时先收紧空行和次要描述，保留聚焦选项、输入行与必要操作。

- 选项：↑↓ 选择，Space 勾选多选项，Enter 提交；←/→ 在选项上或输入光标边缘切题，每题的草稿各自保留。
- 自由回答：末行直接输入文字，可与所选选项一起提交。普通问题的这一行标为 `My view`，聚焦时显示 `❯`；登录表单中显示为中性的 `Input`。
- 长正文：Alt+↑ / Alt+↓ 滚动阅读。
- Ctrl+K 折叠面板后可以继续编辑聊天草稿，再展开会恢复答题草稿。
- Ctrl+V 或 Alt+V 在主动按键时读取剪贴板文本；终端粘贴同样可用。

请求数据可以选用四种呈现：`detail`（正文下加一行说明）、`link`（加一行链接）、`secret`（输入按字符显示为 `•`，提交的仍是原文）、`hideCustomInput`（有选项时隐藏自由输入行，本地向导用它把问题变成纯选项）。

## /login

`/login` 在同一个提问面板里运行本地登录表单，密钥不会进入普通聊天输入、运行时快照、账本或模型上下文。

- 首屏为 Add / Edit：新增包含内置 API、自定义接口和账号授权；账号授权直接启动 OAuth。
- 自定义接口按“名称 → 遮罩的 key → URL 与协议（同一批两题）→ 模型选择 → 最终确认”推进，确认后才保存。协议可选 Chat Completions、Responses、Anthropic Messages。
- 编辑只处理所选字段；删除需要另行确认。新增不能使用已有的服务名，避免换地址后沿用旧凭据。
- 空的可选 key 可以提交，表示匿名发现模型。
- 表单自动获得焦点；Ctrl+K 折叠后可编辑聊天草稿，但登录期间提交聊天或其他命令会被拦截。
- 按需发现模型、授权和保存配置都在这里完成。模型能力编辑器和保存后自动切换模型尚未提供。

管理已有服务用 `/providers`，切换模型用 `/model`。

## 状态栏

状态栏显示当前窗口的模型、思考档位、权限、上下文与任务状态。运行中的角色显示本任务实际模型，空闲时显示下一任务的默认选择。上下文百分比标记为 USED（已用），缺失的用量与价格不会显示成零；用量和费用既不是模型上下文窗口，也不是提供商账单。

`/statusbar`（或 `/settings` 的 Statusbar 标签）编辑状态栏：

| 项目 | 选项或操作 |
|---|---|
| Style | Pipes（首段为角色色粗体，其余为 muted 文字、弱化的 ` │ ` 分隔，进度条填充用角色色）或 Starship（首段为角色色 30% 混入背景的底色加提亮的角色色文字，其余段为贴近背景的深石板蓝底色阶与浅灰文字，Powerline 连接符） |
| Palette | theme（跟随系统语义色）、gruvbox、dracula |
| 模块 | 角色、模型、思考档位、权限、上下文、运行状态、Token、费用、会话、项目目录 |

用 ↑↓ 聚焦模块，Space 开关，←/→ 或 `[` `]` 调整顺序；鼠标点击行切换开关，行末箭头调整顺序。预览使用正式渲染器，只改本地草稿，保存后才生效。切换风格或配色不会重置模块组合。

宽度不够时，按用户排列的顺序优先占位，先使用紧凑写法，再整项隐藏，不会截出半个分段。偏好保存在 `~/.logox/statusbar.json`。

## 字体要求

界面使用 Nerd Font 字形（状态栏图标与 Powerline 连接符），没有 ASCII 回退。

1. 安装带 Nerd Font 字形的等宽字体。推荐 [Maple Mono NF CN](https://github.com/subframe7536/maple-font/releases)（下载 `MapleMono-NF-CN` 压缩包）：英文圆润，中文严格两格宽，并自带 Nerd Font 图标，一款字体就能覆盖中英文和图标。也可以用任意 [Nerd Font](https://www.nerdfonts.com/font-downloads) 的 Mono 变体，例如 `JetBrainsMono NFM`。字体只是推荐，Logox 不绑定任何字体。
2. 在实际运行 Logox 的终端里，把字体切换为它（字体菜单中显示为 `Maple Mono NF CN`）。只下载或安装而不切换，缺字不会消失。
3. 重开终端，检查状态栏图标与 Powerline 接缝是否完整。

## 主题与动效

主题是数据文件。内置主题位于 `src/config/themes/*.json`，用户在 `~/.logox/themes/*.json` 新增文件或同名覆盖即可改色，具体步骤见[配色设置](COLORS.md)。在 `/settings` 的 `Theme preset` 选择主题，结果保存到 `~/.logox/ui-preferences.json`。

主题只管系统颜色（边线、高亮、描述、选区等），切换角色窗口不会变色，切换主题才会变。角色的身份色与卡片底色属于角色配置 `~/.logox/actors/<id>/config.yaml` 的 `color`、`card_closed`、`card_open`，不随主题切换；`config.toml` 的 `[theme]` 仍可做四色覆盖，见[配置示例](../config.example.toml)和[角色模块](modules/actors.md)。

`/settings` 中的 `UI animations and motion waves` 控制动效；关闭后界面保持静态，任务状态不受影响。

系统命令的结果与错误以独立的系统身份显示，不冒充助手回复。显示、保存和送入模型是三件不同的事，详见[系统历史](modules/system-history.md)。
