## 角色定义与配置

Markdown + Frontmatter 表达角色定义，用户级与项目级覆盖，支持后续热加载。每个角色定义包含 prompt、压缩契约和默认模型：prompt 写身份、职责与工作方式；压缩契约引用共用机制并设置摘要重点、数量、预算和触发条件；默认模型以提供商 + 模型 ID 表达。数值用结构化字段，角色表达与摘要要求用可读文字。

Logox 与 Actor 共用压缩服务，Actor 的完整旧轮可为 0，任务结束整理与长任务水位整理并存。Aletheia/Techne 需保留一定工具信息，Kalon 以审美需求和打磨目标为重点；具体各角色的完整旧轮、工具数量与长度预算在剧团阶段讨论，基础接口支持配置。

摘要标题/报告、有效上下文、完成卡片与 Director 交接复用同一产物；主会话压缩以“扬弃”呈现，Actor 整理在幕后展示。算法及保留口径以[上下文设计](2026-10-12-context-compaction.md)为准。

## 默认模型与任务模型

每位 Actor 可配置不同默认模型，未配置时继承当前会话模型。角色模型与主 /model 共用已认证云端、已配置本地及明确无需认证服务目录；同名模型按提供商 + ID 区分。/login 保存的认证、环境与显式配置来源使用相同解析，密钥留在认证层。

开始任务时解析并固定实际任务模型，模型请求、工具往返、计量和窗口预算使用同一身份。主选择或角色配置改变对后续任务生效；明确配置的角色模型不随主 /model 改变。本次任务只在用户同意转用后改变实际模型。

角色请求选择独立于主 Registry，不通过临时 select 主模型执行 Actor。模型改变时使旧用量锚点失效、重新组装有界上下文，原角色账本保留，跨协议内容由 adapter 回放。

Actor 最终模型汇总默认跟随实际任务模型，包括已同意的转用；允许单独覆盖汇总模型。Logox 的默认汇总跟随自己的当前模型，窗口与输出能力由各自实际汇总模型决定。

## 默认模型不可用时的转用

运行时检测默认模型不可用，自动展开所属 Actor 卡片，说明默认模型、原因、拟使用的当前会话模型和已有进展，询问本次是否转用。用户确认前不发替代模型请求，确认只对当前任务有效，不改角色定义或会话主选择；后续任务继续尝试默认模型。

| 情况 | 已确认处理 |
|---|---|
| 模型不存在、认证/权限失效、额度耗尽 | 提出转用 |
| 暂时连接故障 | 有界重试仍失败后提出转用 |
| 用户取消、工具失败、审批拒绝、输出截断 | 沿原取消/失败流程收尾，不提出模型转用 |
| 缺窗口能力 | 提示配置窗口，先解决能力来源 |
| 回答期间会话模型改变 | 更新候选提示，重新确认 |
| 会话模型与失败模型相同或也不可用 | 说明原因并收尾，避免循环询问同一转用 |

请求使用原 activityId 和独立 requestId，复用异步等待与回答校验。明确“转用/不转用”裁决，自由文本不直接当同意。按新 requestId 自动展开一次，用户仍可稍后折叠；主/角色窗口回答同一请求，取消信号优先。

确认后验证提示中的候选仍可用、重新计算预算，只从安全的下一次模型请求接续。已完成工具与结果保留，文件和 Shell 副作用不重放，未完整响应中的工具不执行，完整调用与结果保持配对。转用公开身份可追溯，原始错误正文、头部和密钥不入卡片或账本。

## 管理入口与恢复

计划的 /actors 管理入口展示角色职能、人设、压缩参数、默认模型和继承说明，数据来自角色定义，候选与 /model 共用目录。命令元数据和补全统一接入，页面与 picker 复用 slash 组件；具体编辑方式在角色系统接入时设计。

恢复需保存任务模型、转用请求、续跑检查点和有效上下文分支，并与主会话、角色账本和受支持文件快照协调。Journal 已保存轮次终态、摘要与有效视图；任务模型、转用请求、排队/待回答检查点仍待接入，现有重启不续跑等待中的角色任务。

## Codex 子代理上下文参考

2026-10-12 已核对[子代理线程](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[Responses 多代理协议](https://developers.openai.com/api/docs/guides/responses-multi-agent)与[服务器压缩](https://developers.openai.com/api/docs/guides/compaction)。本机只见 Codex CLI 可执行程序，没有对应源码；以下公开接口与 API 机制分别作为参考。

| 核对事实 | LOGOX 适配 |
|---|---|
| 本次 spawn_agent 可选 all 继承父历史或 none 不传，默认 all | 用任务简报提供所需材料，不自动复制 Logox 全历史 |
| 子代理有自己的线程，可追加 followup_task；interrupt 不删除上下文 | 持久 Actor 接续自身有效上下文，新决定由派工或显式消息交接 |
| Responses 主/子代理独立服务器压缩，使用加密 compaction item | 借鉴独立预算，沿用自身 TSRC 与可读摘要，保持跨提供商能力 |
| final 汇合父代理，工具过程仍在子线程查看 | Director 消费摘要，需要证据再读角色账本；直接 @Actor 不自动推送 |

能查看完整历史、角色能持续存在、下次请求发送哪些历史分别处理。后续 token 控制依靠任务简报、工具保留和有效视图；不把上述 API 机制当成所有 Codex 客户端的固定内部实现。
