# 共用上下文预算与轮次摘要压缩

日期：2026-10-12。状态：Logox 基本上下文管理已实现；真实长对话验收与完整 Actor 接入待完成。先接入 Logox 基本功能，完整 Actor 配置按[迁移顺序](2026-10-11-typescript-migration.md)在剧团阶段接入。

本文维护共用压缩机制、预算、摘要格式和恢复边界；角色默认模型、转用流程与人物定义见[持久角色设计](2026-10-12-persistent-actors.md)。

## 目标与保留范围

保留原 LOGOX 基于轮次摘要复用的 TSRC。Logox 与 Actor 使用同一套工具归档、摘要折叠、上下文组装和恢复机制，差别由角色压缩契约、数值参数与触发条件表达。

完整账本保留，压缩只改变实际请求使用的有效视图。存储原记录不产生模型输入 token；调用开销由实际输入、输出、重试和摘要生成组成。完整工作流程可查看，后续请求使用经过整理的视图。

| 参数/行为 | Logox | Actor |
|---|---|---|
| 完整旧轮 | 默认最近 2 个已结束轮次，可配置 | 可以为 0；具体角色保留值在剧团阶段讨论 |
| 工具原文 | 默认最近 2 条调用及对应结果，跨轮计数 | 按分工配置；Aletheia/Techne 需要一定工具信息，具体值待讨论 |
| 当前工作轮 | 独立保留必要目标、进展、状态和依据 | 同左；旧轮保留 0 不删除当前任务 |
| 整理触发 | 达到窗口阈值时重组历史 | 任务收尾触发，也检查长任务窗口水位 |
| 随轮摘要 | 任务收尾生成，以备压缩复用 | 任务收尾生成，供后续上下文及完成卡片复用 |
| 最终模型汇总 | 默认当前登录并选定的模型，可覆盖 | 默认实际任务模型，包括已确认的转用，可单独覆盖 |

一轮从输入/派工到任务结束，包含多次模型往返和工具调用；同批同角色合并派工形成一个任务。生成摘要与触发历史压缩是不同动作，常规压缩复用已有摘要。

## 摘要与压缩契约

摘要由一句话短标题和简短报告组成。同一标题用于 Actor 完成卡片；展开显示同一报告以及账本中的完整工作流程。有效上下文与必要的 Director 回传复用同一摘要，TUI 不生成另一份摘要。直接 @Actor 的按需拉取规则保持有效。

报告保留后续工作需要的结果、依据、未完成事项和验证状态；工具证据可通过原记录回读。标题尽量一句话说清结果，报告不重复整段工作流程。

| 角色 | 摘要保留重点 |
|---|---|
| Logox | 用户目标、确认决定、执行结果、角色交接、未决事项 |
| Aletheia | 核心发现、证据位置、约束、未查清问题 |
| Techne | 修改位置、实现取舍、验证、失败和待修复事项 |
| Kalon | 审美需求、确认风格、最终取舍和当前打磨目标；工具只留影响判断的结论 |

Logox 与每个 Actor 都有角色 prompt 和压缩契约。prompt 表达身份和工作方式，压缩契约表达摘要格式、保留重点、数量、预算及触发条件；结构化参数与可读文字分别表达，角色文件归属见[角色定义](2026-10-12-persistent-actors.md#角色定义与配置)。

优先在最终回复收尾中一起产出标题和报告，避免常规整理另发全量摘要请求。实现时明确结构、校验与兜底；摘要整理异常不把已成功执行的工作误标为失败。

## 模型能力、计量与水位

模型目录提供上下文窗口和输出能力，配置可覆盖。未知窗口提示配置；输出额度同时受模型能力与剩余输入空间约束。窗口能力不是模型 ID 或累计用量，预留、近期保留量与输出上限分别处理。

计量参考 PI：优先使用最近有效 usage，估算锚点之后的新消息。失败、取消和全零用量不作为可靠锚点；模型、规则/工具集合或有效投影改变后使旧锚点失效。归一输入/输出与缓存字段，避免重复计量；累计调用开销与单次窗口预算分开。

沿用原 LOGOX 的水位思路：窗口 W，预留 R = min(reserve_tokens, W / 4)，触发 H = W - R，可由 max_budget_tokens 压低；整理目标 L = W × low_watermark_ratio，可由 target_budget_tokens 压低。原 reserve_tokens=32768、low_watermark_ratio=0.5 作为迁移参考，输出上限仍独立约束。实现时验证小窗口裁剪与安全余量。

长任务在工具批次完整落账、下一次模型请求前检查预算，整理已关闭的过程。流式响应、审批等待和批次中间保持调用/结果配对；不每次工具调用都额外请求总结。旧用户原文、摘要和备忘录本身的增长也纳入预算。

## 分层整理与失败恢复

1. 归档可关闭的工具原文，落盘确认后使用真实回读位置；正常保留配置要求的最近调用原文。
2. 用已有摘要折叠旧轮，正常保留最近完整旧轮。
3. 仍超目标时将更多旧轮改为摘要，必要时归档正常保护范围内的工具原文。保留数是常规目标，当前目标、工作状态和工具协议配对继续保留。
4. 摘要视图仍达触发水位时，使用该角色汇总模型有界归并旧历史；当前工作轮不混入旧历史备忘录。关闭工具与 thinking，限制输入和输出，只接受有效且确实缩小规模的结果。
5. 归档失败、汇总无收益或仍不能容纳时，保留可恢复视图并提示恢复方式，停止超预算请求。原始账本和已完成副作用不因整理失败丢失。

/compact 强制触发同一套整理，使用相同参数和降级规则，只跳过未达阈值的提前返回。

## 原项目与 PI 的适配依据

| 核对点 | 原实现/参考事实 | TS 选择 |
|---|---|---|
| 轮数 | 原 split_turn_spans 包含当前轮，保留 2 通常为当前轮加 1 个旧轮；原参数至少 1 | 只数已结束旧轮，当前工作轮独立，允许 0 |
| 工具数 | 原 loop 将一批结果存入同一消息，最后 2 个工具消息通常是 2 批 | 按单条 call 身份计数并保留对应结果，跨轮选择 |
| 随轮摘要 | 原最终答复末行一句话，缺失时有界补写或本地兜底 | 明确标题 + 报告结构，常规复用 |
| 最终汇总模型 | 原 app 只使用本地 Ollama/LM Studio，无本地模型就不汇总 | 默认当前选定/实际任务模型，可显式覆盖 |
| 能力目录 | PI 内置窗口/输出数据可逐模型覆盖，自定义缺失时使用通用默认值 | 参考目录和覆盖机制，未知窗口要求配置 |
| 余量 | PI 的压缩预留、近期保留量和 streamSimple 输出余量在不同位置处理 | 各字段独立校验，按实际小窗口裁剪 |

PI 的 provider-composer 按 ID 装配与覆盖能力，compaction 保护工具边界并处理 usage 锚点；LOGOX 保留按轮数/单条工具计数的特点。稳定前缀可使用厂商缓存，缓存仍占窗口，角色与厂商的缓存分别处理。
