## 卡片、留白与选项的取舍

直接输出角色背景 RGB，避免额外与黑底或父卡混色；终端透明合成由终端负责。角色底色保留自身色相与透亮感，展开/悬停更亮。入梦采用白日梦雾白灰背景和深色文字；白色主题指底色。

Logox 的思考/工具无背景，Actor 内部工具和已答记录透出父卡底色。移入收起卡片时提示可点击：有背景卡切换为展开底色，所有可折叠标题使用所属角色高亮色；移开恢复，悬停不展开、不改变答案。

左右各 2 列，正文与长任务完整折行；上下对称。场景角色卡顶部 ▄、底部 ▀ 构成各半行视觉留白，卡片间隙独立于命中范围。选用 BMP 半块字符，依据是实机字体缺少扩展平面块字形。展开正文按分组与细分隔线组织。

选择统一使用 ❯ 和角色高亮文字，说明与标签正文对齐，普通选择使用 Logox 绿色。保留 Claude Code 的导航方式，视觉沿用 LOGOX 自身主题。

## 窗口、输入与复制

@角色快速派发后保持当前窗口；双击卡片、Ctrl+Enter 或 Ctrl+G 进入角色窗口。各窗口独立保存草稿与阅读锚点，主窗口与角色窗口消费同一活动和请求状态。

输入按字形编辑，中文、组合字和 emoji 不拆开。硬换行保留原文，软折行只影响视图；上下移动保留理想列。输入从 1 行增长至最多 5 行，超出后滚动输入视口，矮窗口收缩；确认、换行与问题焦点按 UI-SPEC。

轨道、名牌、封边与填充是装饰，不进入正文复制。SGR 鼠标报告区分移动、单击、双击和拖选；正文选区拼接软折行并保留硬换行，通过 OSC 52 复制。退出恢复鼠标、备用屏和输入模式。

## 表格与代码块的全宽框线

状态：已实现，模拟终端通过。用户要求表格具有完整上下框线，表格和代码块的横线铺满终端可用正文宽度；保留既有身份轨道与终端安全边距。

触发：正式回复包含短单元格表格或 PowerShell 代码块。当前表格只有表头下的分隔线，列宽达到内容自然宽度后停止增长；代码围栏仅显示两个横线字符，所以宽窗口中边框缺失或只有一小段。

方案：表格在自然列宽分配后继续分配剩余宽度，顶部、表头分隔和底部使用一致的列边界。窄屏纵向表格也保留全宽上下横线。代码块开头保留语言标签并补满横线，末尾显示全宽横线；过长标签按完整字形截断，保持单行。布局随窗口宽度重建；框线和列填充不增加复制内容，整块复制仍恢复原始 Markdown。

验收：正式行构建覆盖短表格、长内容、对齐、宽窄屏、流式补齐、代码块与长语言标签；检查完整上下框线的列宽、原文复制和缩放。通过模拟终端核对右侧框线的位置，真实 Windows Terminal 按 [TESTING](../TESTING.md)现场检查。

## 完整滚动链路诊断

复现：构建后运行 `node scripts/bench-scroll.mjs`。脚本通过真实 App、React Profiler、Ink 增量渲染和模拟 TTY，以每 16 ms 一次的间隔发送 80 个滚轮报告；强制 RGB 颜色，输入只使用合成历史。Profiler 测 React 更新，Ink onRender 测文字输出构建，帧间隔取 onRender 时间戳；字节数取模拟 stdout，均不包含真实终端字体绘制时间。

修复前 665e490 的原因与对照：

- App 每次滚轮修改 anchors，重新创建可见行的 React 子树；当前按屏幕 index 给行编号，移动后同一位置的内容整体替换。临时原型用稳定行身份和 memo 复用未变行，在 180×65、50 条的相同重放中，React p95 降到 10.26 ms；Ink 绘制仍 27.85 ms，帧间隔中位数 74.26 ms。原型仅保存在忽略的 diagnostics 目录，未接入正式代码。
- 公共 Ink 8 的 render-node-to-output 每帧遍历 Text，重新 squashTextNodes、执行颜色/字重 transform、测宽并构建输出。增量输出只减少最终差异写入，没有复用滚动前的整块屏幕。可见区域变大时开销明显增长；50 条与 400 条历史的相近结果表明，修复折行缓存后，此复现的主要开销在可见区域绘制。
- CLI 固定 maxFps 30，鼠标每次固定跳 3 行。单独将基准上限改成 60 后，180×65、50 条的帧间隔中位数 48.63 ms、p95 122.30 ms，CPU 时间和写出字节增加，仍存在停顿。去掉颜色后 Ink 中位数降至 20.47 ms，但帧间隔 p95 仍 113.19 ms；颜色处理参与开销，不能通过去掉主题解决整条链路。
- 180×65 的连续重放还输出 Maximum update depth exceeded 警告；行复用原型中未出现。警告触发链还需专门最小化，不把它当作独立已修复问题。

Claude Code 当前源码的实际差异：`src/ink/components/ScrollBox.tsx` 累计滚动量并直接安排渲染，纯滚动绕开逐次 React 协调；`src/hooks/useVirtualScroll.ts` 以 overscan 和分段位置控制组件挂载；`src/ink/render-node-to-output.ts` 复用屏幕内容并产生 scrollHint；`src/ink/log-update.ts` 使用终端滚动区域与 SU/SD 平移旧内容，只补写露出的行；`src/ink/ink.tsx` 单独调度这些成本较低的滚动帧。这些是其自有 Ink 扩展，LOGOX 当前安装的公共 Ink 没有相同接口。

表格最小复现：向 layoutMarkdown 输入两列标准 Markdown 表格，断言输出含排好列的竖线分隔，在 665e490 失败；输出仍为三行原始管线文本。当时 markdown.ts 只有标题、列表、引用、代码围栏和行内语法分支，没有表格识别、列宽分配、对齐或窄屏重排。Claude Code 的 `src/components/MarkdownTable.tsx` 则单独测单元格、分配列宽、折行，并在列过窄时转为纵向呈现。

修复实现（2026-10-12 已授权并接入）：保留公共 Ink 和现有主题。新增终端输出边界，Ink 负责输入区、状态栏、选择器和对话框，会话区域由同一输出边界管理独立画布；Ink 在该区域只保留固定高度的空白占位。所有 Ink 写出经过边界后再恢复会话画布，避免两方各自假设屏幕状态。会话行编码按不可变 Row 缓存，滚轮直接累计到各窗口原文锚点，以 16 ms 帧调度合并输入；匹配旧行时用限定会话区域的 SU/SD 平移，只补露出的行，并立即恢复滚动区域和光标。提交阶段先交接画布区域，缩放、页签/对话框切换和 Ink 重画使画布失效，下一次完整恢复；退出取消未完成帧，清理监听并交还备用屏。普通非全屏和屏幕阅读器使用原 Ink 路径。鼠标命中和复制读取当前画布视口，阅读期间流式追加保持原文锚点，到底继续跟随。表格识别分隔行，按字形测宽和分配列宽，单元格换行、对齐；列宽不足时纵向显示，边框和填充不进入复制，整行/整表复制恢复原始 Markdown。业务运行时不变。
