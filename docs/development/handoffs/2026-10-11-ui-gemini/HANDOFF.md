# LOGOX UI 设计交接 — 给 Gemini

日期：2026-10-11。

请在随附的 `logox-ui-demo.html` 上继续打磨 LOGOX 的 UI。用户已经认可这个版本的整体方向，希望由你优化细节。目标是一个有剧团气质、清晰、紧凑的全屏终端界面。

## 1. 项目与这次任务

LOGOX 正在从 Python 迁移到 TypeScript。新项目名为 `logox-ts`，围绕 **Anamnesis 入梦系统**与**剧团式 subagent 系统**设计，默认 fullscreen。目前选择 Node.js + React/Ink，底层实现参考 Claude Code。

Logox 是主对话中的导演。Aletheia、Techne、Kalon 等 Actor 是有自身身份与表达方式的 subagent；每个角色拥有独立对话和上下文。Anamnesis 在合适时机整理、研究和核验记忆，不应打断用户继续输入。

**这次工作是 UI 细节打磨。** 当前 HTML 是可交互的设计 demo，任务执行、工具结果和记忆候选是场景数据；实际 Ink 界面尚未套用这个版本。请保留现有信息组织和交互语义，改进视觉及使用细节，给出能落到 TUI 上的方案。

## 2. 用户已经明确的要求

### 2.1 整体风格

- 参考旧 LOGOX 和 Claude Code 的终端风格：等宽文字、紧凑布局、少量必要装饰，重点是对话与工作过程。
- 默认全屏，消息历史、当前工作与输入区要形成清楚的阅读顺序。
- 不要堆按钮、导航条、角色徽章或复杂容器。用户已经要求移除顶部窗口按钮组、发送按钮及 Actor 卡片上的导航按钮。
- 有角色个性的短表达和动作描写可以保留，例如 Kalon 的审美判断；不要把剧团全部处理成没有身份的日志。

### 2.2 左侧装饰轨道

- 延续旧 LOGOX 的左侧轨道设计，清楚区分用户的问题与 Logox 的回答。
- 用户与 Logox 使用不同颜色。当前基准是**用户蓝色、Logox 柔和绿色**。
- 轨道是装饰，**不能进入复制的正文**。不要在消息字符串中插入 `▎`、竖线等字符来实现轨道。
- Logox 指派的 Actor 任务卡片，按顺序嵌在对应的 Logox 回复轨道下。
- 用户在主对话明确 `@kalon` 时，用户消息仍使用用户色；Kalon 的对应回复/任务卡所在轨道使用她的代表色。Kalon 的代表色是**紫红色**。其他角色采用各自的身份色。

### 2.3 正文与普通卡片

- **用户的问题、Logox 的回复不装在消息卡片里。** 直接在轨道旁展示正文。
- 角色独立窗口里的普通对话正文也直接展示。
- 工具调用、可展示的思考内容等，各自形成可折叠的普通卡片。可显示类型、摘要、文件/命令与状态，展开后看详细内容。
- 普通卡片使用中性背景，与 Actor 卡片明显区分。
- **所有卡片标题前不要有 `》`、`>`、`›`、折叠三角或其他展开箭头。** Actor 的身份符号不是展开箭头；输入区的终端提示符也不属于卡片。

### 2.4 展开与折叠的表现

- 使用背景深浅区分展开与折叠，同时通过内容是否出现表达状态。
- **展开：背景透明度低，颜色更实。**
- **折叠：背景透明度高，颜色更轻。**
- 只改变背景，不对整张卡片设置低透明度；文字一直保持清晰。
- 角色卡片与普通卡片均可折叠展开，状态更新留在原位置，不应不断追加相同任务的卡片。

### 2.5 Actor 卡片

标题形态：

```text
✧ Kalon · 校准首页的字体、颜色和留白                 排队中
```

- 结构是：**符号 + 角色名 + 分隔点 + 做了什么**。右侧可以保留简短状态。
- 使用角色色的背景和身份文字，让用户一眼分清这是一个角色任务入口，而非普通工具记录。
- 标题尽量紧凑。窄终端可以换行，不能挤压正文、截断关键任务或堆成多层大卡片。
- 不显示 `ACTOR /` 前缀、冗余角色副标题。
- **不在卡片上显示“进入对话”按钮、“双击进入独立对话”等操作提示。**
- 单击折叠/展开，双击进入对应 Actor 的独立历史。

### 2.6 快速派任务与角色独立窗口

这是两条入口，指向同一个 Actor：

1. **在 Logox 主对话输入 `@kalon ...`**：快速派任务，用户仍留在主对话，看到对应的角色任务卡。
2. **双击 Kalon 卡片**：进入 Kalon 的独立对话窗口，查看她的详细历史，也可以继续直接给她发送消息。

角色历史必须按时间记录：

- Logox 给该角色的任务、补充和协作消息。
- 用户直接给该角色的消息。
- 用户通过主窗口 `@角色` 派发的消息，并标明来源。
- 角色的回复、工具调用及可展示的思考内容。
- 权限询问、用户裁决、Agent 提问与用户回答等对应过程。

不要把“用户在 Logox 窗口 @Kalon”错误标成“Logox 给 Kalon 的任务”。需要清楚区分发信方、接收方和来源窗口。

主窗口中的任务摘要与角色窗口中的详细过程引用同一次任务。进入/返回窗口不新建角色、不重发任务、不重复历史。各窗口保留自己的草稿，返回主窗口也保留卡片的折叠状态和任务状态。

### 2.7 可复用状态与异步交互

- subagent 工作状态卡与 Agent 提问、权限提问卡要可复用；角色任务和 Anamnesis 的活动都围绕共享展示/交互协议组织。
- 提问体验参考 Codex 的异步提问：可选择选项，也能补充自己的文字；允许稍后处理，主输入仍可使用。
- 权限卡清楚说明要执行什么、影响什么，本 demo 提供“允许这一次”和“不允许”。
- 问题不是全局模态弹窗，不应把其他输入或任务卡锁住。
- 同一个问题在主窗口或角色窗口处理后，其他入口同步更新，不能重复回答。
- 收起或暂缓问题不代表拒绝、取消或回答完成。
- Anamnesis 的进度、暂停/继续、候选待核验等状态也要能沿用同一套卡片语言。记忆候选与已经写入的记忆需要清楚区分。

## 3. 可以重点打磨的细节

以下是设计任务，不是已经锁死的具体数值：

| 细节 | 希望改善的体验 |
| --- | --- |
| 配色与对比度 | 深灰底、清晰正文，身份色有辨识度又不过分抢眼；Kalon 继续用紫红色 |
| 普通/Actor 卡片差异 | 除颜色外，用紧凑的文字层级与间距体现工具记录和角色任务的不同 |
| 展开/折叠背景比例 | 不靠箭头也能辨认，长篇展开时背景不过分厚重 |
| 轨道与缩进 | 连续对话归属明确，嵌套过程不让正文区域越来越窄 |
| 工具与思考详情 | 长路径、命令、代码、输出和 diff 易读，收起后摘要仍有用 |
| 状态文案 | 排队、运行、等待回答、已完成、失败、取消和暂停简短而明确 |
| 异步问题 | 待回答时容易找到，又不挤满主对话；选项和自由回答保持终端感 |
| 双击与单击 | 双击进入历史时不先明显展开再收起，切换窗口不跳失草稿或阅读位置 |
| 角色历史 | 区分 Logox、用户和角色自身的记录；长历史中仍能判断任务及工具过程的归属 |
| 窄终端与全屏阅读 | 角色名、任务、状态和正文能合理换行；输入区与历史的滚动关系明确 |

当前 demo 的精确色值、角色符号、背景混色比例、间距、默认折叠状态都可以改善。整体信息结构与上面的明确要求应保留；有必要改变交互语义时，先说明具体收益与代价。

## 4. 当前 demo 的体验路径

浏览器直接打开 `logox-ui-demo.html`。无需启动服务或安装依赖，刷新页面恢复初始场景。

1. 初始是 Logox 主对话：“打磨作品集首页”。普通工具/思考卡片与三个 Actor 卡片都在同一轮回复下。
2. 点击工具或 Actor 标题，检查无箭头的展开/折叠和背景变化。
3. Techne 卡片请求修改两个文件。可以确认许可，也可以暂缓，继续在主输入说话。
4. 初始输入预填了 `@kalon 看一下首页配色。只给建议，先别改文件。`。Enter 派发后仍停留在 Logox，新增 Kalon 任务卡的轨道为紫红色。
5. 双击任意 Kalon 任务卡，查看她与 Logox、用户的历史以及 Read、思考记录；直接给她补充要求。
6. Esc 返回主对话，检查各窗口的草稿与主窗口卡片状态仍然保留。
7. 处理 Techne 的权限后，Kalon 的偏好问题可以在主窗口或角色窗口回答。回答后，两边同步更新，并出现 Anamnesis 偏好候选。
8. Aletheia 和 Techne 的卡片也支持双击进入各自历史。

当前键位：Enter 发送/确认；Shift+Enter 在主输入换行；Esc 暂缓当前问题或返回主窗口；聚焦 Actor 标题时 Ctrl+Enter 进入角色历史。输入法确认中文候选时不发送消息。

## 5. TUI 落地需要说明的地方

- 最终实现是 React/Ink 终端界面。HTML 是设计与交互交流载体，不能依赖浏览器专属控件、阴影、动画或布局机制作为最终设计前提。
- “背景透明度”在真实终端可表现为预先混合的背景色；保持展开更实、折叠更轻的视觉关系即可。
- 本 HTML 轨道用无文字的 CSS 装饰绘制。TUI 方案要说明轨道怎样与可复制正文分离，以及在目标终端如何验收复制行为。
- 工具、权限、任务取消和历史归属由运行时处理。UI 负责展示与输入，不能通过换页面或收卡片触发新的任务副作用。
- 用终端列宽描述布局和截断规则。建议至少检查 80 与 120 列；HTML 可同时检查宽/窄尺寸。

本地源码可用时参考：原 `Logox/src/logox/tui/`、`claude-code-source/src/`；新项目为 `logox-ts`。迁移目标见 [迁移总览](../../designs/2026-10-11-typescript-migration.md)，终端实现取舍见[舞台设计](../../designs/2026-10-11-terminal-ui.md)，本交接文件是截至本日期的 UI 要求摘要。
