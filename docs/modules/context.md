# 上下文管理

模型每次请求能带的内容有上限，但完整的过程记录不应该因为压缩而丢失。这个模块把“原始账本”和“发给模型的视图”分开：账本只追加、不改写；每次请求时再从账本里挑出当前需要、预算装得下的部分。

## 核心概念

- **Journal（账本）**：每个会话、每个角色的原始 JSONL 记录，只追加。恢复和回读都以它为准，见 `src/store/journal.ts`。
- **轮（round）**：从一个活动的最初输入，到它完成、失败或取消。同一活动中途注入的协作消息不另算一轮。
- **有效视图**：本次请求真正带上的历史，由账本经过归档、折叠、收缩得到，账本本身不变。
- **`_FinishRound`**：每个正常结束的轮会调用的隐藏工具，用来提交这一轮的内部记忆。它不显示成工具卡片，也不算用户授权。
- **轮次关闭时的送达判定**：模型若只回复了文字而没有调用 `_FinishRound`，这段文字就算已送达（只持久化一次），运行时只追加一次请求要求它调用 `_FinishRound`。这次请求的工具列表和工具发现设置与普通请求完全相同（工具列表在缓存前缀的最前面，不能变），只靠一条仅限本次请求的提示约束。追加请求的回复若包含业务工具、不合格的参数、纯文字或空内容，业务工具不执行（给一条“轮次正在关闭”的错误结果以保持账本配对），运行时代写带 `[runtime]` 标记的记录，轮次照常结束，不再追问。真正没有任何交付文字的空回复仍先得到一次固定提醒。派出工作的报告由运行时按根任务成批送达（见 `docs/modules/actors.md`），Logox 只在它们到齐或有紧急事件时才被唤醒，所以关轮不再需要“仍有未结束工作”的提示和“迟到报告”的特殊路径。
- **`_FinishRound` 参数与记录**：只有 `title`（上限估算 30 token）和 `summary`（上限估算 200 token，非 ASCII 字符计 1，ASCII 计 0.25），不规定语言。工具描述引导 `summary` 覆盖结论或改动、涉及的文件、验证了什么、还剩什么，不拆字段也不校验。参数宽进：超长截断不报错，缺失的 `title` 由运行时取阶段行或派单标题，未知字段忽略，旧字段 `outcome`、`verification`、`carry_forward` 会被合并进 `summary`；只有 `summary` 为空才算不合格。旧会话文件里的 `outcome` / `verification` / `carryForward` 读取时合并成 `summary`，不改写文件。
- **运行时代写的记录**：被用户或 Director 中断、失败、或正常结束但模型没给出可用摘要的轮，正文由运行时根据这一轮账本里的事实写成，开头带标记：`[interrupted]`、`[failed]`、`[runtime]`。内容是 Edit/Write 改动的文件和最后一条 Shell 命令的退出码；正常结束但缺摘要的轮还会附上所交付回答的开头，这是最接近模型自己结论的内容。同样受 200 token 上限约束。
- **高水位 / 低水位**：高水位是触发整理的上限，低水位是整理后要降到的目标。整理会重置提示词缓存，所以触发后一次降到低水位以下，而不是零碎地压。
- **ContextManager**：每次请求前组装有效视图的组件。

## 一次请求前发生什么

1. 根据角色、本任务实际使用的模型、轮次和工具身份，从账本组装有效视图。真人输入、派工、角色报告和协作消息保留各自的来源，角色的数据不会被当作人工授权。
2. 估算 token 是否超过高水位。没超过就直接发送。折叠已结束的轮不调用模型，时机见下文“轮次开始时的折叠”；Logox 平时保留完整历史，Techne、Kalon、Aletheia 在新任务开始时折叠旧轮。
3. 超过时依次整理，每一步后重新估算：
   1. 较大的旧工具参数和结果归档到磁盘，视图里只留可回读的指针。
   2. 已结束的轮折叠成单行索引：`T<序号>|<标题>|<摘要>|<起>-<止>`（四列，无空格），内容来自这一轮 `_FinishRound` 的记录；状态不再单独成列，异常轮次以摘要开头的方括号标记表示。先折叠保留窗口（`keep_recent_rounds`）之外的轮，仍超过低水位时折叠全部已结束的轮。被钉住的轮（见下文）排在最后：全部折叠后仍不低于高水位才折叠它们。
   3. 索引行本身仍使请求不低于高水位时，才请模型把最旧的若干条索引行（连同已有的概览）合并成一份工作概览，条数以降到低水位以下为准，上限约 4000 token。这是唯一一次由模型写的合并，输入只有索引行和旧概览，不含整段对话；也只有索引行是超线原因时才发生（当前任务自身过长则走第 4 步）。
   4. 当前任务自身仍超过高水位时，由模型写一份进度摘要，替换这个任务已完成的过程，原始输入保留。

   第 4 步在对话末尾追加一条整理说明，让本任务的模型直接总结，这样请求能复用已缓存的对话前缀；汇总模型与任务模型不同或总结失败时，退回到程序提取。第 3 步用不带对话的独立请求，输入过长时分段汇总。
4. 仍无法容纳，就停止这次业务请求并说明原因；原文和已完成的操作不受影响。

整理在完整的工具批次边界进行，不会把一次工具调用和它的结果拆开。`/compact` 手动触发同一套阶梯（强制执行，不要求先越过高水位）。模型没有写出可用摘要、由运行时代写 `[runtime]` 记录的已完成轮和其他轮一样折叠，索引行里是运行时记下的事实和回答的开头，完整过程仍可按行号从账本取回。

**轮次开始时的折叠**：折叠只是把已结束轮的起点记入保存的视图，不调用模型。它在一个会开启新一轮的活动开始时、第一次模型请求之前运行；协作提问、同伴唤醒、回复和中途插话产生的活动不是新的一轮，不触发。折叠是否损失提示词缓存取决于替换点的位置：

- **同伴（Techne、Kalon、Aletheia）**：替换点永远在历史末尾，之后没有内容需要重写，所以无条件折叠，没有半水位下限，也没有收益门槛。若新任务与该同伴最近一个已结束轮属于同一个根任务（返工、续做；比较已保存的任务检查点里的 `rootActivityId`），上一轮细节保留、什么都不折叠；否则折叠全部尚未折叠的已结束轮，包括上次被保留的那一轮。
- **Logox**：它的轮是人的消息，运行时无法判断是否续做，所以保留固定窗口（`keep_recent_rounds`，默认 2）。检查点是每个 Logox 活动开始时（新一轮开始，或派工之后的验收续接同一轮）；一个活动内部的工具循环不再检查。两个条件满足任一个就折叠到只剩最近两轮：缓存已过期（现在减去账本中最后一条助手记录的时间戳不小于缓存时长，重启后仍有效），或估算的请求不小于高水位的一半。缓存时长由 `src/providers/cache.ts` 的 `cacheLifetimeMs()` 给出：Anthropic 是 Logox 自己设置的 5 分钟或 1 小时；OpenAI 和其他服务未知，除非配置了 `cache_ttl_seconds`（见[使用指南](../USAGE.md)）。未知视为永不过期，只靠半水位和水位线触发。
- **钉住异常轮次**：状态为失败或被中断的轮保持完整细节，上述折叠都不碰它，只有水位线兜底在别无办法时才折叠。解除钉住有两种情况：被续做（`resumeTask` 开出的新活动正常完成）；或它的根任务已结束——同伴被 Director 派发的轮，以 Director 账本里已有覆盖该根活动的轮记录为准（Director 账本里找不到该活动时看根活动是否已处于终态）；Logox 的轮，以及没有 Director 派发人的同伴任务，以之后有一轮正常完成为准。解除后按普通轮折叠，渲染运行时代写的 `[interrupted]` / `[failed]` 行。
- 折叠会重置思考的有效范围（`thinkingCut`），与水位线整理一致。折叠状态与整理视图一起保存在上下文状态文件里，重启后保持。同伴的这类折叠静默进行；Logox 的折叠发一条简短的 `[Context] Folded N closed rounds ...` 提示；水位线整理和 `/compact` 仍发 `[Context] Compacted ...`。

旧配置里的 `keep_index_lines`、`task_end_floor_ratio`、`compact_accept_ratio` 已退役：配置文件和角色 `config.yaml` 里仍可保留这些键，加载时直接忽略。

整理之后，整理点之前产生的思考内容不再发送，工具调用和文字保留。Anthropic 新模型的思考块签名绑定了它之前的全部内容，整理后这些内容已经变了，继续发送会被拒绝；其他服务也不需要这些旧思考。

## 保留多少原文

默认值来自各角色 `config.yaml` 的 `context` 配置：

| 角色 | 保留的近期完整轮 | 保留原文的近期工具次数 |
|---|---|---|
| Logox | 2 | 2 |
| Aletheia、Techne | 0 | 2 |
| Kalon | 0 | 0 |

当前正在进行的轮和还没配对的工具批次另有保护，不会被折叠。

## 水位与预算

高水位 = `min(max(窗口 - 输出预留, 窗口 × high_watermark_ratio), max_budget_tokens)`，`high_watermark_ratio` 默认 0.8，保证小窗口模型也有可用空间。例如窗口 1,000,000、预留默认 32,768，且没设预算上限时，高水位是 967,232；窗口 32,768 时是 26,214。低水位只是整理的目标，不会提前触发整理。参数见[配置示例](../../config.example.toml)。

模型窗口按“配置覆盖 → 服务目录 → 内置能力资料 → 模型名推断”的顺序取得。未知的模型需要自己配置 `context_window`；本地服务要填实际分配的窗口，不要填型号的理论上限。内置 `gpt-6.1-sol` 的窗口是 1,000,000，显式配置仍可覆盖。

token 估算（`TokenMeter`）优先用上一次响应的真实 usage 作为锚点，再估算之后新增的消息。换模型或换工具集会让旧锚点失效。图片 base64 不计入文本，每张图暂估 1,200 token，这是预算估计，不是供应商的精确计费。

## 系统提示与工具披露

系统提示固定六个主题，按变化的可能性从上往下排：`Persona`、`Execution Rules`、`Team Collaboration` 是固定文本；之后是 `Project Guidelines`、`Tools & Skills`、`Current Environment`。两部分之间有一个缓存边界，固定部分在换项目、开新会话时仍能命中缓存。模型、权限、恢复和能力的变化不改动系统提示，而是作为程序来源的 `context` 记录追加到历史末尾，不冒充用户任务。

工具定义按需披露：支持的服务（如原生 Anthropic、OpenAI Responses）只先发送工具名，模型需要时再展开完整定义；不支持的兼容端点直接发送完整工具集，不保证省 token。整理历史时，会保留证明“这些工具已被发现”所需的最少记录，旧记录不会让已移除的工具恢复可用。这套估算是本地保守估算，不调用额外的计数接口。

## 用量与费用

任务、汇总和审批的用量都记入同一个 `UsageLedger`。`/usage` 按静态价格表估算费用，缺少 usage 或价格时不会伪造精确账单；回退对话不会删除已发生的消费。

## 边界与限制

- 压缩从不改写或删除账本的原始行；摘要里的位置引用的是账本中的真实行号。
- 恢复只恢复记录和有效视图，不重放历史工具。`/rewind` 之后，未来的内容不会因为缓存重新进入请求。
- 摘要来源改变或归档缺失时，回落到原文；原始账本损坏则直接报错。
- 失败、取消或元数据缺失时，使用保守兜底，保留实际交付和真实终态，不编造“已验证”。
- 压缩调用模型时仍可能失败、取消或产生费用，它不等于无限上下文。
- 大块工具输出存放在所属账本的 `.tools` 目录，按指针回读时仍要通过权限检查。

细节和不变量见[上下文路标](../../src/context/AGENTS.md)。

## 源码入口

- [manager.ts](../../src/context/manager.ts)：有效视图、轮次开始时的折叠、分层整理与汇总。
- [budget.ts](../../src/context/budget.ts)：水位、估算和 usage 锚点。
- [cache.ts](../../src/providers/cache.ts)：缓存时长 `cacheLifetimeMs()`，供 Logox 的缓存过期判断和缓存保活共用。
- [contracts.ts](../../src/context/contracts.ts)：摘要、检查点与本地兜底。
- [round-memory.ts](../../src/context/round-memory.ts)：`_FinishRound` 元数据与四列索引；对应的隐藏工具在 [_FinishRoundTool](../../src/tools/protocol/_FinishRoundTool/_FinishRoundTool.ts)。
- [continuity.ts](../../src/context/continuity.ts)、[environment.ts](../../src/context/environment.ts)：压缩后保留的工具发现与环境基线。
- [usage.ts](../../src/context/usage.ts)：持久用量与费用估算。
- [journal.ts](../../src/store/journal.ts)：原文、分支、归档与绑定验证。
