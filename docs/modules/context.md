# 上下文管理

模型请求不能无限增长，完整记录也不应因压缩而丢失。Logox 将原始账本与发送给模型的有效视图分开：界面和回读保留原始过程，请求只携带当前需要且预算容纳得下的部分。

## 当前行为

每次模型请求前，ContextManager 根据角色、任务模型、轮次和工具身份组装上下文。真人输入、派工、角色报告与协作消息保留不同来源；角色数据不能被当成人工追加授权。

任务结束保存标题、报告和完成/失败/取消状态。普通轮次摘要尽量从同一次最终回复提取，缺少格式时采用本地兜底，不为每次收尾额外请求一次模型。提示词要求英文四部分摘要，但 schema 主要校验标题与报告长度，不能把格式要求写成代码强制保证。

Logox 默认保留近期两轮和两次工具原文；内置 Actor 默认保留零个完整旧轮，Aletheia/Techne 保留两次工具，Kalon 不保留旧工具原文。角色可配置保留参数；当前工作轮与尚未配对的工具批次另行保护。

## 整理流程

1. 归档较大的旧工具参数与结果，保留可回读指针。
2. 用已有摘要折叠旧轮，保留近期原文和当前目标。
3. 仍超过预算时进一步收缩有效视图。
4. 必要时用汇总模型分段生成历史备忘录；默认跟随实际任务模型，也可显式配置。
5. 无法安全容纳时停止业务请求并说明原因，原文和已完成操作仍保留。

水位由真实窗口、输出预留和 context 参数共同决定，见[配置示例](../../config.example.toml)。`/compact` 强制运行同一整理流程；自动整理在完整工具批次边界执行，不会为了压缩拆开一次工具调用和结果。

Actor 正常任务结束会整理，异常时先保存本地摘要并及时交接，下次请求再补做必要折叠。压缩会调用模型时仍可能失败、取消或产生费用，不等于获得无限上下文。

## 能力、用量与费用

模型窗口来自配置覆盖、服务目录、内置能力资料或模型名推断。未知能力需要配置 `context_window`；本地服务应填写实际分配窗口，不能把型号的理论上限当成本次服务能力。

TokenMeter 优先使用有效 usage 锚点，再估算后续消息；更换模型、工具集合或投影前缀会使旧估计失效。任务、汇总和审批用量分别记入同一 UsageLedger。缓存计数按协议归一，避免重复计算输入。

`/usage` 根据静态模型价格估算费用，缺少 usage 或价格时不会伪造精确账单。回退对话不删除已经发生的消费，恢复也不重复计费。

## 数据与失败边界

Journal 保存原始 JSONL，轮次、有效分支、工具归档和上下文检查点另存。检查点绑定原文长度与哈希，写入确认后才采用新视图；来源改变或归档缺失时回落原文，损坏原始账本则报告错误。

较大的工具内容保存在所属账本的 `.tools` 目录，可按指针回读并继续接受权限检查。摘要的路径和行号基于真实记录，不用视图轮号冒充文件位置。

恢复只恢复记录和有效视图，不执行历史工具。`/rewind` 排除未来活动后，旧摘要必须仍与有效来源匹配；未来内容不能因缓存重新进入请求。未完整助手/工具消息的配对修复也只发生在投影中，不重放副作用、不改写旧账本。

## 源码入口

- [manager.ts](../../src/context/manager.ts)：有效视图、分层整理与汇总。
- [budget.ts](../../src/context/budget.ts)：水位、估算和 usage 锚点。
- [contracts.ts](../../src/context/contracts.ts)：摘要、检查点与本地兜底。
- [usage.ts](../../src/context/usage.ts)：持久用量与费用估算。
- [journal.ts](../../src/store/journal.ts)：原文、分支、归档与绑定验证。

测试入口：[上下文](../../tests/context.test.ts)、[预算与恢复补充](../../tests/context-extra.test.ts)。操作见[使用指南](../USAGE.md)。
