# 上下文管理

本页说明实际模型请求怎样从完整账本中取得有效上下文。操作见 [USAGE](../USAGE.md#上下文与扬弃)，方案与验收见[压缩设计](../development/designs/2026-10-12-context-compaction.md)。

## 从完整记录到模型请求

Journal 保留每个会话、每个角色的原始 JSONL。ContextManager 在每次模型请求前读取它，按轮次、工具身份和已保存视图组装请求。TUI 仍显示原始工作流程；压缩不删除历史，也不执行工具。用户记录的 inputKind/source 决定请求中的来源说明：角色派工、报告与协作作为角色数据包装，审批另取真人授权；旧 JSONL 只投影，不改写。

一轮由用户输入开始，到该活动完成、失败或取消结束。Ensemble 将终态、来源范围、原文哈希及标题/报告另存为 .rounds.json。普通收尾从同一次最终回复提取【轮次摘要】；格式缺失或无效时使用本地兜底，不增加模型请求。失败和取消的摘要明确保留未完成状态；摘要保存失败也不将已经成功的工具工作改判为失败。

Logox 按水位触发整理。Actor 正常任务结束按自己的保留参数整理；异常终止先保存本地轮次摘要、立即交接，不等待模型压缩。下一次 Actor 请求补折叠尚未整理的已结束旧轮，继续遵循 0 个完整旧轮和角色各自的工具保留数。

新版本保留旧 JSONL 消息格式。旧会话缺少终态/摘要时，已进入下一输入的轮次可以折叠，摘要采用本地兜底；没有依据时不补造完成状态。历史恢复只展示记录，不自动续跑工具。

## 模型能力与用量

能力取值顺序是当前模型的 provider 覆盖、models 中的提供商/模型覆盖、服务模型目录元数据、内置 PI 0.87.1 公开能力快照。内置快照只用于对应官方地址；未知窗口要求配置真实 context_window，本地填写服务实际 num_ctx。换模型或提供商后，不继承原模型的窗口覆盖。DeepSeek 的摘要助手消息也补齐空 reasoning_content，沿用 PI 的协议兼容方式。

TokenMeter 优先复用同模型、规则、工具集合和投影前缀的有效用量，估算其后的消息。任一绑定变化、失败/无效结束或全零用量使锚点失效；重启重新计量。Anthropic 缓存读写计入总输入，OpenAI 兼容接口的缓存读取属于 prompt_tokens，不再次相加。

模型请求同时受窗口、水位、输出能力和 provider.max_tokens 限制。最近请求占用和已记录的任务/汇总用量在 /status 展示；没有返回 usage 的调用不虚构用量，连接检查不计入任务统计。TokenMeter 同时生成任务/汇总及模型归属记录；UsageLedger 按会话/角色保存，重启恢复计数但不恢复估计锚点。/usage 按模型静态价格计算费用，缓存从总输入中扣出后分别计价，缺少价格显示未知。

## 分层整理

Logox 达到高水位时执行；Actor 每任务结束执行，长任务仍检查水位；/compact 强制执行同一流程。角色契约与参数来自[角色目录](actors.md)，三位 Actor 默认保留零个完整旧轮，工具分别保留 2/2/0；以下两轮、两次工具是 Logox 默认值：

1. 将较大的旧工具参数和结果归档，保留最近两条调用及结果的原文。
2. 复用已有摘要折叠旧轮，常规保留最近两轮已结束对话；旧用户输入保留原文，当前工作轮独立。
3. 超过低水位目标时，允许进一步折叠旧轮及归档保护范围内的工具原文。长任务只整理已经闭合的过程，当前目标和最新工具批次继续保留。
4. 仍达高水位时，用汇总模型分段归并旧历史。默认使用当前选定模型，可在 context 配置覆盖；当前工作轮不进入备忘录。每段输入/输出有界，最多十六段，只接受完整且缩小规模的正文。
5. 无法容纳时停止业务请求并说明恢复方式，保留原文和已完成副作用。

工具计数按单条调用而非批次，跨轮选择。折叠时按身份保留对应调用与结果，不留下孤立结果。完整助手消息保留提供商要求回传的思考/签名；折叠整轮后使用摘要，不重新复制该轮思考。只有思考、没有正文和工具调用的中断消息仍留在原始账本和界面中，但不作为空助手消息发送。

请求投影在对应工具批次结束处补齐中断结果，保证它们位于后续用户输入之前。孤立或重复工具结果转为带说明的历史资料。以上修复只影响请求视图，不执行工具，不改写原始账本。

## 保存、恢复与失败

较大工具原文以内容哈希存于所属账本的 .tools 目录，指针同时保留成功/失败状态。read 可按真实路径读取；私人运行目录仍遵循工具许可规则。轮次摘要附带真实 JSONL 路径和物理行号，不使用视图轮号推断行号。

.context.json 保存来源长度/哈希、折叠范围、归档身份、历史备忘录和当前进展。归档写入及检查点原子保存成功后才使用新视图；写入失败保留原视图。恢复验证来源前缀、覆盖范围及归档内容，原分支改变或文件缺失时回落原文。坏原始 JSONL 仍报错，不跳过错误行来伪造回读位置。

/compact 运行时禁止新任务和模型切换；取消与关闭传播到汇总请求并等待收尾。重复整理不重复插入摘要。Actor 整理失败保留已成功任务的终态与原账本。ContextManager 的调用身份保留 activityId，自动压缩的过程与结果通过系统历史关联原 Actor 卡片；收起时一同隐藏，展开和重启后仍保留关联。手动 /compact 的报告关联本次整理活动。独立任务模型、转用后预算和汇总身份来自同一 TaskModels；角色压缩契约参与普通摘要指令与最终历史汇总。会话回退按原文有效分支筛选角色历史和直接对话索引，不重放工具。

## 会话切换与回退

`Journal.loadRaw` 读取完整原文，`load` 返回有效分支，`inspect` 诊断完整前缀。回退通过 session 级分支清单同时排除各角色的目标活动，轮次摘要与压缩状态使用分支文件；仅继承仍与有效前缀绑定的内容，未来摘要失效后从有效原文重建。归档和摘要的引用映射到连续物理行段，避免跨过被排除的原文。

会话替换会重建 ContextManager，用共享 UsageLedger 恢复当前 session/owner 的消费；候选创建前 flush，恢复不重复 charge，回退不删除实际消费。Registry 与 Resources 在项目层复用，普通请求与 /compact 共用资源；/reload 使当前估算前缀失效。完整规则及验证见[会话专题](../development/designs/2026-10-12-session-management.md)。
