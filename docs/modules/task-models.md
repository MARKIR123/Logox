# 任务模型与确认转用

会话用的模型不一定适合每个角色，所以 Logox 把“会话选择”“角色默认模型”“这次任务实际用的模型”分开。这个模块保证请求、预算、用量和界面讲的是同一个模型，并在模型出问题时让用户决定要不要临时换一个。

## 核心概念

- **模型身份**：提供商加模型 ID，不是一个可能重名的字符串。
- **会话模型**：用户当前在界面上选的模型。
- **角色默认模型**：给某个角色单独绑定的模型，见[角色与协作](actors.md)。
- **任务实际模型**：任务开始时定下来的那一个，运行期间不再变动。

## 怎么确定模型

1. Logox 自身使用会话模型。
2. 其他角色有默认模型就用它，否则继承任务开始时的会话模型。
3. 任务开始后固定配置和能力，不跟着界面上的选择漂移；认证仍每次请求时从共享认证存储读取。

上下文窗口和输出额度按任务实际模型计算，汇总默认也跟随它（可显式覆盖）。用量统一记入 TokenMeter 和 UsageLedger，没有另一套隐藏的费用统计。

## 什么时候询问转用

只有角色显式配置了默认模型，又遇到明确的模型缺失、认证或额度问题时，才可能询问是否“仅本任务”改用会话模型。

| 错误类别 | 处理 |
|---|---|
| `model_missing` | 要有明确的模型不可用依据，普通 404 不算 |
| `authentication` | 认证或权限错误，可进入确认 |
| `quota` | 明确的余额或额度耗尽，可进入确认；并非所有 429 都是额度问题 |
| `temporary` | 传输、超时、限流等暂时错误，走原有的有界重试 |
| `capacity` | 窗口未知等能力问题，要求配置，不自动转用 |
| `protocol` | 参数或协议格式问题，不自动转用 |

继承会话模型的任务、Logox 自己、已经转用过的任务，以及候选模型和失败模型相同的情况，都不会询问。用户取消、工具失败、审批被拒或输出被截断也不是换模型的理由。

确认时可以先检查候选模型的能力，但不会向它发请求；只有明确选择同意才转用，自由输入文字不算。候选变化时重新确认，取消优先。单次决定不会写回默认模型，下一个任务重新读取默认值。

## 转用后怎么接续

1. 失败请求已显示的内容保留在原角色记录里，未完整的工具参数不执行。
2. 确认后重新准备有效上下文和预算，已完成的工具及结果保留，不为换模型重跑文件、Shell 或扩展操作。
3. 请求中会去掉旧模型的签名思考，避免把一家服务的签名发给另一家；账本里的原文仍在。

错误分类只保留识别后的公开诊断，不把完整响应、响应头或凭据放进确认问题或账本。

## 检查点与恢复

`TaskModelLedger` 记录会话、角色、活动、初始与实际模型、继承或转用标记和阶段，不保存密钥；恢复时按 Journal 里当前有效的活动过滤，被回退的任务不会再影响模型状态。重启后可以恢复模型的展示和摘要身份，但不恢复待回答的确认，不自动请求模型，也不重放历史工具。

## 源码入口

- [task-models.ts](../../src/actors/task-models.ts)：任务 scope、确认与模型账本。
- [registry.ts](../../src/providers/registry.ts)：模型选择、能力与共享认证。

- [manager.ts](../../src/context/manager.ts)：实际模型下的投影和预算。
