# 任务模型与确认转用

会话模型不一定适合每个角色。本模块将“会话选择”“Actor 默认模型”和“这次任务实际模型”分开，保证请求、预算、用量和界面说的是同一个身份。

## 模型怎样确定

Logox 使用会话选择。Actor 有默认模型时采用它，否则继承任务开始时的会话模型。模型身份由提供商和模型 ID 共同组成，不仅是一个可能重名的字符串。

任务开始后固定配置与能力快照，运行期间不会跟着主界面选择漂移；认证仍按请求从共享认证存储读取。角色默认绑定、项目定义和交互设置见[角色模块](actors.md)及[使用指南](../USAGE.md)。

ContextManager 按本任务实际模型计算窗口与输出额度。汇总默认跟随相应角色的实际模型，可由显式摘要配置覆盖；用量统一进入 TokenMeter 和 UsageLedger，不建立另一套隐藏费用统计。

## 何时询问转用

仅当 Actor 显式配置了默认模型，且遇到明确的模型缺失、认证或额度问题时，才可能询问是否**仅本任务**改用会话模型。

| 错误类别 | 行为边界 |
|---|---|
| `model_missing` | 要有明确模型不可用依据，普通 404 不一律猜测为模型缺失 |
| `authentication` | 认证或访问权限错误，可进入确认流程 |
| `quota` | 明确余额/额度耗尽，可进入确认流程；并非所有 429 都是额度问题 |
| `temporary` | 传输、超时、限流或暂时服务错误，沿既有有界恢复处理 |
| `capacity` | 窗口未知等能力问题，要求配置，不自动转用 |
| `protocol` | 参数或协议格式问题，不自动转用 |

继承会话模型的任务、Logox 自身、已转用任务，以及候选与失败模型相同的情况，不循环询问。用户取消、工具失败、审批拒绝或输出截断也不当成模型替代的理由。

确认前可以检查候选能力，但不发送候选生成请求；只有明确选择同意才转用，自由文本不冒充同意。候选发生变化时重新确认，取消优先。下一任务重新读取角色默认值，不把单次决定永久写回默认模型。

## 接续与安全边界

失败请求已显示的内容保存在原角色记录中，未完整的工具参数不执行。确认后重新准备有效上下文与预算；已完成工具及其结果继续保留，不为了换模型重跑文件、Shell 或扩展操作。

跨模型转用时，请求投影移除旧模型的签名思考，避免把一家服务的签名送给另一家；原始账本仍保留。新模型产生的有效签名再按它的协议处理。

错误分类只保留识别后的公开诊断，不把整段服务响应、响应头或凭据塞入确认问题或模型账本。

## 检查点与恢复

TaskModelLedger 保存会话、角色、活动、初始/实际模型、继承/转用标记和阶段，不保存密钥。恢复按照 Journal 当前有效活动过滤，被回退的任务不能重新影响模型状态。

重启可以恢复实际模型展示与摘要身份，但不恢复待回答确认、不自动请求模型、不重放历史工具；后续任务重新开始自己的模型选择流程。

## 源码入口

- [task-models.ts](../../src/actors/task-models.ts)：任务 scope、确认与模型账本。
- [registry.ts](../../src/providers/registry.ts)：模型选择、能力与共享认证。
- [http.ts](../../src/providers/http.ts)：服务错误分类和协议请求。
- [agent.ts](../../src/kernel/agent.ts)：失败请求收尾与转用后的循环。
- [manager.ts](../../src/context/manager.ts)：实际模型下的投影和预算。
