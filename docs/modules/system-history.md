# 系统历史与环境通知

命令结果、程序错误和环境变更既不是助手的回复，也不一定该交给模型。这个模块把“怎么显示”“存不存”“给不给模型”三件事分开，避免界面通知污染对话，或者被当成人工授权。

## 核心概念

- **系统事件**：带稳定 ID、时间、类别、会话、角色和可选活动身份的一条记录。
- **展示位置（`presentation`）**：由发出事件的一方显式标注，界面不会根据文案猜。
- **Journal**：会话的权威账本，系统事件单独存放，不混入 user/assistant/tool 的模型记录。

## 展示位置

| 位置 | 内容与行为 |
|---|---|
| `silent` | 登录取消、模型/思考档位切换等已在当前页面体现的结果，不额外打印 |
| `status` | 设置已保存等普通回执，在状态栏短暂提示，连续提示替换同一位置 |
| `panel` | `/skills`、`/models`、`/help`、`/commands` 等查询结果，进入只读面板，Ctrl+C 复制全文，Esc 返回并保留草稿 |
| `timeline` | 必要的全局错误和重要事件；全局错误默认显示摘要，可展开；带活动身份的任务错误仍挂在原任务上 |
| `welcome` | 仅在没有对话和任务的空白会话中显示，开始任务后消失 |

异步查询会先打开临时加载页，并记住发起时的会话、角色和面板；结果只更新原面板。面板已关闭时，迟到的成功只留审计记录，迟到的失败退回到所属角色的全局错误。

## 保存与恢复

1. 空白的临时会话先缓冲系统事件，首次正式任务登记后一并写入。
2. 正式会话按队列写入，关闭时等待收尾；保存失败会保留缓冲并报告，不会假装已写入。
3. 恢复时按事件 ID 去重，回退只过滤对应活动的事件，原始记录保留；恢复不会重新弹出提示或自动打开结果面板。

实际恢复依据的是 Journal 里的事件文件；`sessions/<sessionId>/events.json` 只是便于人读的镜像，不是权威来源。欢迎信息、复制提示等短暂的界面状态不会都写入历史。

## 哪些内容进入模型

| 内容 | 模型如何处理 |
|---|---|
| 本地命令结果、页面与命令错误 | 只展示和保存，不变成模型消息 |
| 模板展开后的任务 | 作为正式任务输入 |
| 工具失败 | 保留与调用配对的 tool result |
| 角色报告与故障交接 | 按角色来源携带必要状态，不算新增授权 |
| 实际执行环境的变化 | 下一次请求按角色补充最新状态 |

“执行环境”包括实际任务模型、思考档位、权限边界、工作目录、scratchpad、规则版本和服务连接。恢复时从有效历史取回最初基线和最新快照，变化在下一次请求作为带程序来源的 `context` 记录追加，不修改已有的系统提示。准备请求或取消不会提前消费变化；只打开设置页面也不会自动开始任务。故障预算耗尽只表示当前任务的限制，下一个任务不会因此收到虚假的“工具恢复”通知。

## 状态栏

应用提供当前窗口的真实状态，TUI 负责布局和裁剪。运行中的角色显示本任务实际使用的模型，空闲时显示默认模型；排队的任务不会遮住正在运行的模型。布局和动效偏好存放在 `~/.logox/statusbar.json`（兼容读取旧目录），保存成功才发布新设置。状态栏字段不影响模型上下文、权限和账单。
