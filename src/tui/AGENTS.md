# Module: Terminal UI (`src/tui/`)

## 1. Scope
- **Owns**: React/Ink presentation under `src/tui/` (entrypoints `app.tsx`, `application.tsx`), terminal output coordination, timeline projection, local form editing and theme consumption. By inheritance also the slash command surface `src/commands.ts` (`commandCatalog`) and `src/commands/surfaces.ts` (`CommandSurfaces`), and the demo scene `src/demo.ts` with `src/demo/`.
- **Does not own**: Runtime execution and the store ([`src/runtime/AGENTS.md`](../runtime/AGENTS.md)); Actor profiles ([`src/actors/AGENTS.md`](../actors/AGENTS.md)); provider authentication and credential persistence ([`src/providers/AGENTS.md`](../providers/AGENTS.md)); theme palette and statusbar preference storage ([`src/config/AGENTS.md`](../config/AGENTS.md)); tool-owned UI modules ([`src/tools/AGENTS.md`](../tools/AGENTS.md)).
- **Design rationale**: [docs/UI-SPEC.md](../../docs/UI-SPEC.md); [docs/modules/README.md](../../docs/modules/README.md)

## 3. Common Changes
### Add a statusbar module
1. Add the id to `statusbarIds` and a label to `statusbarLabels` in `src/config/statusbar-preferences.ts`. New ids append disabled to saved layouts; `defaultStatusbar` enables only the first six (role, model, effort, permission, context, cache; git and cost stay off).
2. Add a `Descriptor` (`icon`, color `token`, `build`) to `registry` in `status/statusbar.ts` and give the id a place in `statusbarPriority` (narrow-width order). It is typed `Record<StatusbarId, Descriptor>`, so a missing entry fails typecheck. `build` returns whole variants from longest to shortest; never truncate text inside a variant. Add its hover detail to `status/notification-line.ts:widgetDetail` (and `widgetCommand` if a click acts).
3. If the module needs data not on `StageStatus`, extend `src/runtime/stage-status.ts` and populate it in `src/application-status.ts`. A variant list that returns `[]` hides the module (cost, cache and git do this when there is nothing to show). Anything that changes the footer without touching the store or statusbar preferences must call the application's `bumpStatus()` (permission mode, git, usage restore).
- Tests: `tests/statusbar-modules.test.ts` (iterates `statusbarIds`), `tests/statusbar-customization.test.tsx`

### Add a slash command
1. Add an entry to `commandCatalog` in `src/commands.ts` (`name`, `usage`, `description`, `argument`). Completion, `/help` and the reserved-name check for custom commands all read this list.
2. Handle it in `src/application.ts`: simple actions are an `if (text === '/name')` branch in the command dispatcher (near `/help`, `/skills`, `/reload`); tabbed pages are added to `src/application-commands.ts:createCommandTabsFor()`.
3. Report through the existing receipt or surface helpers with an explicit `presentation`; never classify text in a renderer.
- Tests: `tests/command-surfaces.test.ts`, `tests/statusbar-customization.test.tsx` (catalog and completion discoverability), `tests/slash-receipts.test.ts`

### Add a tab or page to a command surface
1. Build the `CommandTab` (`id`, `title`, `lines` or `toggles`) in `src/application-commands.ts:createCommandTabsFor()`, and extend `ApplicationCommandContext` for any new data.
2. Persist edits in `saveConfigToggles()` (same file), dispatched by tab id from the `onSaveToggles` callback in `src/application.ts`.
3. `src/commands/surfaces.ts:CommandSurfaces.openPage()` and `panels/tabbed-page.tsx` render it with no changes; a single-tab page hides its tab bar.
- Tests: `tests/settings-interaction.test.tsx`, `tests/tabbed-page-single.test.tsx`, `tests/command-panels.test.tsx`

## 4. Hard Boundaries
- **Only `app.tsx` and `application.tsx` are root source files**: every other module sits in a responsibility directory; `components/` depends only on neutral foundations, and production never imports `previews/`. No global "utils" or "types" catch-all directories. Enforced by `tests/tui-module-layout.test.ts`, which lists every file per directory, so adding or moving a file means editing its `layout` map.
- **Colors come from semantic palette tokens**: no color literals in UI source; theme revision invalidates App memoization, timeline projection and encoded rows. Enforced by `tests/color-literals.test.ts`, `tests/theme-colors.test.ts`.
- **/ensemble is one plan and one reducer**: `panels/ensemble-layout.ts:ensembleLayout` returns the rows and every hit region, `stepEnsemble` runs keyboard, mouse and footer-button commands; data comes pre-resolved from `src/commands/ensemble-model.ts:buildEnsemble` (roster order, per-actor tools through `ToolRegistry.resolveForActor`, MCP servers as folders, skills by scope), `/actors` no longer exists, and editing is delegated to `src/commands/editor.ts:openInEditor` (`$VISUAL`, `$EDITOR`, OS opener; never inside the TUI). Resources have no file watcher, so edits take effect after `/reload`. Enforced by `tests/ensemble-page.test.tsx`.
- **Command pages carry explicit rows**: producers build `CommandTab.rows` with `src/commands/tab-rows.ts:row` (`heading`, `field`, `text`, `bullet`, `rule`, `blank`); `panels/tabbed-page.tsx:tabDisplay` word-wraps with a hanging indent and draws rules at the page width. Plain `lines` render as text and are never promoted to label/value by guessing at a colon. The permission mode is edited as a page-local draft (`CommandTab.mode`): Space/m/←→ mark it unsaved, Enter alone sends `set_mode:<id>` and the host saves and closes with a receipt. A tab action may return `confirm` (inline yes/no, used by provider logout) or `close`. Enforced by `tests/command-pages.test.tsx`.
- **Command pages**: `/animations` is an alias of `/settings`; `/config` is a read-only page with no mutation; drafts update synchronously and a pending save locks same-chunk input; a tab-page save that is not the last one keeps the page and other drafts open. Enforced by `tests/slash-commands-decoupled.test.ts`, `tests/settings-interaction.test.tsx`, `tests/statusbar-customization.test.tsx`.
- **`/settings` is its own surface (`kind: 'settings'`), not a tabbed page**: rows are data (`src/config/settings-definitions.ts`), the page keeps drafts, and only Enter (or Ctrl+S) hands the changed values to `CommandSurfaces.saveSettings`. Drawing, hover and every click region come from one plan (`panels/settings-layout.ts:settingsLayout`), keyboard, mouse and the footer buttons run the same `SettingsCommand`s, and the page never reads a store itself. Theme drafts preview live and `CommandSurfaces.cancel` reverts them. A `Pages` row opens its sub-page over the settings (`CommandSurfaces.openSettingsPage`) and Esc returns with the drafts intact; sub-pages reuse `TabbedPage` and the same `PageActions` as `/statusbar` and `/permissions`. Enforced by `tests/settings-page.test.tsx`, `tests/settings-integration.test.tsx`, `tests/command-surfaces.test.ts`.
- **Presentation settings are read live, never threaded through props**: renderers read `src/config/ui-settings.ts:uiSettings()` (thinking display, tool tint, diff layout, splash options, enter key, notify) and `applyUiSettings` invalidates every cached layout through the theme revision (`src/config/theme-palette.ts:invalidateTheme`). Enforced by `tests/settings-behaviours.test.ts` and `tests/focus-reports.test.tsx`.
- **Terminal focus and notifications**: `terminal/focus.ts` turns focus reports (DECSET 1004, enabled with mouse tracking in `app.tsx`) into `terminalFocus()` and strips them from the key stream (`FocusReportFilter`; the `stdin.read` wrapper in `app.tsx` swallows a focus-only chunk by reading again, never by answering `null` after data, which drains the event loop and silently exits the process); `terminal/notify.ts:RoundNotifier` rings once when a busy stretch of 30 s or more ends. No report means unfocused. Enforced by `tests/settings-behaviours.test.ts`.
- **Empty lists explain themselves**: a picker that loads empty hides the search box and shows `emptyText` with the next action (`/rewind`, `/model`, `/resume`); `/login` Edit with no saved providers flashes a hint. Result panels may carry styled `lines` (tone `title|strong|pass|warn|fail|muted`, as `/doctor` does) instead of raw ANSI. Enforced by `tests/command-pages.test.tsx`.
- **System feedback**: hosts assign `presentation`; saves flash in the footer, replay never re-toasts or reopens results, results scope to owner and session. Enforced by `tests/system-notices-ui.test.tsx`, `tests/command-result.test.tsx`, `tests/command-receipt-races.test.ts`.
- **Input intent**: Enter submits as `queue`; a running target holds the message in the pending list directly above the composer (`input/input-delivery.ts:pendingRowLayout`, rows `Queued · Send now  ×` (`Restored · Send  ×` for a message loaded from a previous session), newest 3, height subtracted from the timeline and command menu, controls drop out as the width narrows, mouse hit regions come from the same layout), never in the timeline; `Send now` click or Ctrl+T on an empty draft steers it into the running round (`· steered` user row), `×` returns the text to the composer; Ctrl+Q is unbound (XON/XOFF); fullscreen Enter inserts a newline and Ctrl+Enter submits as `queue`; Ctrl+T with a draft steers an exact activity; `app.tsx` is the sole native cursor owner; failed or stale deliveries keep drafts; Queue/Steer never cancels a task. Enforced by `tests/fullscreen-composer.test.tsx`, `tests/fullscreen-editor.test.tsx`, `tests/input-queue-ui.test.tsx`.
- **Composer has no fill and no placeholder**: compact/fullscreen bodies inherit the terminal background; only selected text receives a background fill. The compact composer's first line leads with a two-column `❯ ` prompt (continuation lines pad two spaces) and both hairlines are tinted by the window actor (`ownerColor(currentView, roles)` mixed 45% into `palette.bg`, prompt 90%); layout, caret and mouse hit-testing all subtract `promptWidth` in `app.tsx`. The fullscreen editor has no prefix. Status bar (theme palette) and actor pills derive from the same actor colour via `appearance/colors.ts:mixHex` (`status/statusbar.ts`, `status/actor-pills.tsx:computeActivePills`). Enforced by `tests/composer-clean.test.tsx`, `tests/fullscreen-composer.test.tsx`.
- **Composer editing**: compact/fullscreen share a grapheme-indexed draft and selection. History is scoped to session/window and human inputs, restoring the scratch draft on return to newest. Main-window Esc restores the stopped task's latest human input only into an empty draft; state updaters and pending acknowledgments preserve newer edits. Menu, selection, question, Actor-back and fullscreen-back Esc retain priority. Enforced by `tests/fullscreen-composer.test.tsx`, `tests/fullscreen-editor.test.tsx`.
- **Main-window Esc is two-level**: the first press stops only the Logox round (or, with Logox idle, only warns) and the notice names the actors still working; a second press within `runtime/round-scope.ts:ESC_STOP_WINDOW_MS` (any other key ends the window) stops every open non-user-started actor activity from `src/runtime/round-scope.ts:roundScope` through `onCancel` (user reason, queued first). Tasks the user started in an actor window, actor-window Esc, per-card Stop and Ctrl+C exit are untouched. Enforced by `tests/stage-controls.test.tsx`.
- **Two-row footer**: row 1 is the status line (`status/statusbar.ts:statusbarLayout` plus right-docked pills), row 2 the notification line, shown only when a real status source exists and `screenRows >= 8` (otherwise `footerHeight` is 1 and a notice replaces the status text, the old behaviour). Row 2 shows exactly one thing by priority: a held notice (`flash(text, ms, tone)`; success `✓`, warning `▲`, error `✗`; system status messages take their tone from `systemEventKind`), else the hover detail of the widget or pill under the mouse, else `notification-line.ts:footerHints`. Timeline, pending rows and menus subtract `footerHeight`. Enforced by `tests/footer-widgets.test.ts`, `tests/footer-hover.test.tsx`.
- **One plan for drawing and hit-testing**: `statusbarLayout` returns the parts and the `WidgetRegion`s from the same plan, and `computeActivePills` returns `startX`/`endX` from the width it renders (compact glyph-only pills, then oldest dropped, when they overflow). Hover is one target per widget (a faint actor-tinted background, never a layout change); clicks run `widgetCommand` (`/model`, `/effort`, `/permissions`) for the current window. Enforced by `tests/footer-widgets.test.ts`, `tests/footer-hover.test.tsx`.
- **Every interactive surface takes the mouse, from one layout**: click selects or activates, hover recolors in the window actor colour (`terminal/mouse.ts:HoverColorContext`, provided with the mouse feed by `MouseHost` in `app.tsx`; read by `useHoverColor`), the wheel scrolls or moves the selection, and keyboard behaviour is unchanged. Surfaces subscribe through `useMouse` and read the pointer with `usePointer`; regions are `Region`s (`inRegion`) computed in the same pass that draws: `components/panel-frame.tsx:panelRows` (body and footer rows), `footerParts` / `hitFooter` (clickable labels inside the footer hint text; a label cut by the width is not clickable), `panels/toggle-list.tsx:toggleZone` (row, `‹`, `›`), the tab cells in `panels/tabbed-page.tsx` and `panels/picker.tsx` (including the single-label narrow form), and `EditorCell.hit` in `panels/permissions-editor.ts` (`reduceClick` maps every hit onto the keyboard transitions). Never add a second set of coordinates or a hard-coded row. A picker click focuses first and activates on the focused row (selection pickers can be destructive); the command menu only selects. New interactive text must be a `hit` cell, a footer label or a `Region`. Enforced by `tests/tui-mouse-surfaces.test.tsx`, `tests/statusbar-customization.test.tsx`, `tests/permission-card-app.test.tsx`. Hover on timeline-hosted approval and question option rows is *Unenforced* (they click but do not recolor).
- **Narrow widths drop whole widgets**: admission follows `statusbarPriority` (role, permission, context gauge, model, effort, cache, state, git, session, project, tokens, cost) at each widget's shortest variant, then widens in the same order; the gauge shrinks to 8 cells before it is dropped; the user's module order only sets display order. No variant is truncated. Enforced by `tests/footer-widgets.test.ts`, `tests/statusbar-modules.test.ts`.
- **Context gauge accounting**: the total is the accurate `StageStatus.context.tokens`; `categories` come from `src/context/breakdown.ts` (local CJK-aware estimates as weights, largest-remainder allocation so the parts sum exactly) and are rebuilt with every reading, so compaction resets them. The hover detail (`status/notification-line.ts:contextDetail`) shows percentages of the window and degrades by width without ever clipping: full names, then abbreviations (`sys pr ast th tl`), then no `free`, then no category list, finally `ctx NN% · compacts NN%`. Enforced by `tests/footer-widgets.test.ts`, `tests/status-live.test.ts`.
- **Selection and mouse**: statusbar drag selects only status text (row 1) and writes OSC52; row 2 is passive; actor pill double-click locates the latest card. Enforced by `tests/statusbar-selection.test.tsx`, `tests/actor-pills-locator.test.tsx`. Timeline drag taking priority over folding is *Unenforced*.
- **Rail ownership**: Director, Actor, human and system rails use their own identity tokens (the Director window shows every actor card under the Director rail); collaboration interruptions use `directorIntervention` for the label only. The outer rail (columns 0-1) of every row inside an open actor card, including groups, stage rows, edit runs and `Message from` cards, keeps the surface colour (Logox in the Director window); only the card's inner `│` rail (`scene.ts:insetRailFrame`) uses the actor colour, and the tint never covers the outer rail cells. Enforced by `tests/stage-process.test.ts`.
- **An actor card has one rail and one stage path**: every row of `tools/orchestration/ActorTool/UI.ts:renderActivity` (stage lines through `group-row.ts:pushStageLine`, tool groups, prose, collaboration cards) hangs off the same `actorTreeFrame`, so the col-0 rail and indent never drift; there is no phase-heading path and a `### ` line in prose is ordinary markdown. The round's report closes the card after the transcript, and a completed round whose transcript already holds the whole reply body does not repeat it (the Goal/Status/Reply wrapper is peeled first, so wrapped reports dedupe too; there is no message id on the summary, so a report that differs from every message stays visible). Enforced by `tests/actor-card-flow.test.ts`.
- **One header per speaker turn**: `timeline/stage.ts:buildStageRows` groups messages into rounds (a user message ends the round; a system row or a new speaker starts the next). Each round prints `<name>` once; actor cards, tool groups, thinking and narration inside it never reprint it, and an actor's own window groups the same way. The header is spliced in when the round closes so it can show the macro activity `<name> · <stage>` (`timeline/stage.ts:buildStageRows` `describeRound`): the stage is the round's latest `⏵` narration (just the name when none was written), never a tool title, `Thinking` or an elapsed time; temporary states from `temporaryState()` replace the stage while they hold (`Awaiting your answer` / `Awaiting approval` from a pending interaction of that owner; `Retrying (n/m)` from `Activity.phase === 'retry'` plus the counter in `Activity.detail`, which the agent loop's `Network retry` report writes; `Compacting context` from `Activity.phase === 'compacting'`, bracketed by `ContextManager`'s `compacting` hook in `src/application.ts`; `Waiting on <Names>` while the round has only running actors left); the header carries no spinner, clock or animation (only actor cards and running rows animate), and a finished round keeps its last stage as muted text. Actor cards use the same `temporaryState()` for their subtitle (`activityTitle`), never a tool title, and keep the last stage when finished. Enforced by `tests/stage-header-activity.test.ts`, `tests/timeline-turns.test.ts`.
- **Rail glyph and quiet rail**: the rail is always exactly two columns (selection and hit-testing assume it). A turn-header row sets `Row.railGlyph` (user `❯`, Logox `◈`, actors their symbol) and `timeline/row-presentation.ts:railCell` draws it bold in the speaker color in both `app.tsx` and `terminal/terminal-plane.ts`; every other row draws `│ ` mixed toward the background (`appearance/colors.ts:quietRail`). Enforced by `tests/timeline-turns.test.ts`.
- **One thinking row per round or open actor card**: thinking never draws between tools; `timeline/stage.ts:buildStageRows` folds all of a round's thinking into one expandable row directly under the speaker header (first row inside an open actor card), `Thought N times · <duration> · <tokens> tokens` (`Thought for 7s` for one; italic title), and while a thought runs the earlier look: the actor's own `thinkingAnimation` glyph, `Thinking` with the shimmer and a live clock. The body has no per-thought duration column: each thought opens with a faint `∴ ` and wraps under a hanging indent, text is muted italic, one blank row separates thoughts. Its fold id is the first thought's message id. Enforced by `tests/thinking-groups.test.ts`, `tests/timeline-turns.test.ts`.
- **Background means expanded**: folded rows and cards never carry a background; an expanded card (tool, thinking, actor) gets `appearance/colors.ts:expandedTint(color, depth)` (the surface owner's color mixed 6% / 11% / 16% into `palette.bg` by nesting depth, carried by `FrameWrap.depth`: open actor card 1, a tool or group inside it 2, a tool inside an open group 3; Logox's own cards start at 1), so a child block never matches its parent. No `▄`/`▀` caps, a header flush after the rail (`▾` plus the title in `palette.fg`) and a body indented two columns that uses the full width (no cap). Folded actor cards stack with no spacer between them. Enforced by `tests/timeline-turns.test.ts`, `tests/stage-interaction.test.tsx`.
- **One anatomy for every tool card**: tool UIs build a `timeline/tool-card.ts:ToolView` (summary pieces after the title plus a rendered body) and call `renderToolCard`; they never draw bodies themselves. The elapsed time is faint and inline (` · 1.8s` right after the content; never mid-row or right-aligned), the far right end of a row is reserved for run state (`■ Stop` / `Stopping…` on a running tool in `tool-card.ts:CANCELLABLE_TOOLS`, today Shell, a `stop_actor` control whose `foldId` is the message id, handled by `app.tsx:stopActor` through `onCancelTool` -> `Application.cancelTool` -> `src/tools/process.ts:killActiveProcess`; nothing for finished tools), long titles clip with `…` inside the row, and a failure shows its reason once (red, no trailing `Error`; a denial keeps a leading red `Denied`). The body shows at most `TOOL_BODY_LINES` (12) rows and then exactly one `… N more lines` (`hunks` when the cut is at a hunk boundary) expander row, which is the fold `<messageId>-more` (own hover brightening and underline, click and Ctrl+N / Ctrl+O toggle it, part of the message layout cache key in `timeline/stage.ts:buildStageRows`); once expanded the body shows everything and the same row becomes `… show less` at its end (`tail` bodies (Shell) keep the toggle above the tail). The thinking body uses the same single expander, counting lines across all thoughts. Empty results draw one italic faint line, failures show the reason in the summary (red) and the full text below, links are underlined (`SceneSegment.underline` in both `app.tsx` and `terminal/terminal-plane.ts`), and a `fixed` card (an image, a CancelActor row, a browser action without a useful body) has no fold. The unknown-tool default (`timeline/tool-ui.ts:renderDefaultTool`) and the generic MCP card use the same anatomy: aligned `key  value` argument rows (`keyValueLines`), then the result (`tool-code.ts:resultLines`, Markdown when it looks like Markdown), `No output` when empty; Q/A conversations use `labelledLines`. Enforced by `tests/tool-card.test.ts`, `tests/tool-views.test.ts`, `tests/tool-ui-unified.test.ts`.
- **Browser calls form their own `Browser` group**: `timeline/tool-groups.ts:groupToolMessages()` never mixes page actions (`browserAction()`) with Read/Grep/Glob/Shell runs; even one browser call is a group (`ToolGroup.kind === 'browser'`), drawn by `timeline/group-row.ts:browserGroupRow()` as `▸ Browser · N actions`. Its children are the `mcp` UI's plain-language rows (`src/extensions/browser-ui.ts:browserRow`). Enforced by `tests/tool-ui-unified.test.ts`, `tests/tool-groups.test.ts`.
- **Hidden tools draw nothing on success**: `src/tools/ui-registry.ts:isVisibleToolMessage` keeps a `hidden` or `silent` tool out of the projection (and so out of tool groups and blank-row accounting); a failed call is visible and renders one quiet row through `timeline/tool-ui.ts:hiddenToolUI` (red `▮`, muted label, red reason, no `Error` label). The fallback `timelineRows` still drops them. Enforced by `tests/tool-ui-unified.test.ts`, `tests/tool-ui.test.ts`.
- **Actor-to-actor SendMessage is not in the Director timeline**: `timeline/stage.ts:projectMessages` drops them via `src/tools/coordination/SendMessageTool/pairing.ts:hiddenFromView` unless Logox is sender or recipient, and passes `pairSendMessages()` results (`ToolRenderContext.pairing`, part of the layout cache key) so a card always shows the question it answers. Enforced by `tests/tool-ui-unified.test.ts`.
- **Workspace-relative paths**: tool titles show paths inside the cwd relative to it (`src/tools/ui-format.ts:relativeToCwd`), absolute elsewhere. Enforced by `tests/timeline-turns.test.ts`, `tests/tool-ui.test.ts`.
- **Animation safety**: backgrounds and column widths stay static, only fixed-width glyph slots animate, and optional motion never changes task state. The 200 ms pacing for up to eight frames is enforced by `tests/actor-thinking-animation.test.ts`; the 130 ms ten-dot Braille pacing is *Unenforced*.
- **Tool UI is tool-owned**: registered tool UIs own formatting; hidden tools have no visible or selectable surface; rendering never executes a tool. Enforced by `tests/tool-ui.test.ts`.
- **Expandable cards draw no `▮`**: tool groups and the "Task from" card lead with ▸/▾ via `pushOrdinaryCard({expandable: true})`; the whole title row (including the elapsed time) hovers and toggles through `:title_*` selection keys. Italic means summarised process (thinking title, group titles); individual tool rows stay upright. A group header is `<verb> N <noun>` per category (`timeline/group-row.ts:groupVerb()` picks a stable word per group id from the actor's `activity_verbs` pool, gerund while running, past when done), italic, white (`palette.fg`) while running and muted when finished. A collapsed running group shows each running tool as a `└` row (`timeline/group-row.ts:visibleRunningCalls()`, kept at least 700 ms per tool id); expanded groups show none. A running single-tool `▮` breathes between muted and the role color on the 200 ms frame rhythm. Enforced by `tests/tool-group-render.test.ts`.
- **A `⏵` stage is its own prose row**: the stored assistant message keeps its raw `⏵` first line (`src/kernel/model-turn.ts` and `src/kernel/reply.ts` must not strip it from the store; renderers call `runtime/narration.ts:stripNarration`). `timeline/tool-groups.ts:groupToolMessages({stages: true})` emits a `StageLine` item exactly where the stage changed (it also ends the current run), and `timeline/group-row.ts:pushStageLine` draws it as wrapping prose in `palette.fg`, upright, with no `⏵` and no glyph, so progress reads intent, its tools, next intent, its tools. Groups never carry or show the intent (no one-member groups either). `timeline/stage.ts:buildStageRows` keys each stage to the next drawn message (or the actor card that follows); the actor card body does the same in `src/tools/orchestration/ActorTool/UI.ts`. The live header and the card subtitle use the current stage (with the temporary overrides above). Enforced by `tests/narration.test.ts`, `tests/tool-group-render.test.ts`, `tests/tool-groups.test.ts`, `tests/stage-process.test.ts`.
- **Same-file edits fold into one row**: `groupToolMessages` also emits an `EditRun` for consecutive Edit calls (and Write overwrites with a known diff) of one owner on one path with nothing drawn between them (thinking and silent tools do not break it; a stage, another tool, file or owner does). `src/tools/EditTool/UI.ts:renderEditRun` draws `Edit(a.css) ×4 · added 4 · removed 4 · 0.4s` through the shared `renderToolCard` (counts and time summed, red mark with the failed call's reason, the combined hunks with `⋯` between edits behind one expander, fold id = first edit's message id); `timeline/stage.ts` maps the run to its first message and skips the others. Enforced by `tests/stage-process.test.ts`, `tests/tool-groups.test.ts`.
- **Only a drawn actor card splits a tool group**: the card draws once at its activity's first message, so later messages of a running actor never break the Director's run (`timeline/stage.ts:buildStageRows`). Enforced by `tests/tool-group-render.test.ts`.
- **Swarm rows**: `src/tools/orchestration/AutomaTool/UI.ts:UI` renders `step.swarm` as an expandable card (`Drone swarm · 4 drones · 3 returned · 12.1s`, same header rules as tool groups). Collapsed, only running jobs show as `└` rows whose frame and clock are drawn by `timeline/row-presentation.ts:decorateRow` from the row animation (keys ending `:swarm_icon` and `:swarm_time`), never by a timer; expanded, each job is a nested card with the fold id `<messageId>-job-<index>` (read through `ToolRenderContext.isOpen`, and part of the message layout cache key in `timeline/stage.ts`) showing its calls and receipt. Jobs still queued or running in an ended step render as `interrupted`; messages without `swarm` use the default card. Enforced by `tests/automa-ui.test.ts`.
- **Hit regions**: a folded card or row is interactive only over its text extent (rail and trailing blanks excluded, `scene.ts:pushOrdinaryCard` `headerCols`); an open tinted card is interactive over its whole block, so a click on blank tint toggles it closed while children's own hits (rows, expanders, links, Stop controls) come first in `SceneRow.hits` / `controls`. Hover recolors the mark, every ` · ` and the title with the card owner's color (`FrameWrap.surfaceColor`, also `SceneRow.hoverColor` on every card row), never the Logox accent inside an actor card. Enforced by `tests/card-interactions.test.ts`, `tests/card-row-consistency.test.ts`.
- **Card row consistency**: `timeline/scene.ts:pushOrdinaryCard` enforces three rules for every single-line card row (tools, thinking, groups, Task from, Message from, SendMessage). (1) Every ` · ` is its own `palette.muted` segment (`SceneSegment.separator`); on hover the mark, separators and title take the owner's color. (2) The hover/click region runs from the leading icon or ▸/▾ to the last non-blank cell of the content (the `■ Stop` slot at the far right is its own control). (3) Hover recolors muted segments with the surface owner's color, read from `FrameWrap.surfaceColor` (set by `appendActorCard` to the actor's color and by `createBuilder`'s `surfaceColor` argument to the view owner on the timeline), never from the card's `ownerId` or sender; semantic colors (sender names, error red, running white) are kept. An actor card's own header rows (name, title, status, arrow, stop) set `SceneRow.hoverColor` to that actor's color (the rail keeps the surface color), so their row highlight never takes the hosting surface's color. Enforced by `tests/card-row-consistency.test.ts`.
- **No artifact blank rows**: `timeline/scene.ts:pushMarkdown` trims leading and trailing blank lines (and draws nothing for blank text), `pushProse` and `pushOrdinaryCard` drop trailing newlines and trailing empty body lines, and thinking text goes through `compactParagraphs()` (no empty rows at the edges or between paragraphs; stored text is unchanged). Interior blank lines of tool output and Markdown paragraph breaks are content and stay. Enforced by `tests/stage-blank-rows.test.ts`.
- **Login secrets stay local**: never in runtime questions, transcripts or model context; one keyboard owner for runtime questions. Enforced by `tests/login-panel.test.tsx`, `tests/question-panel.test.tsx`, `tests/fullscreen-composer.test.tsx`.

- **A failure card never repeats its title as body**: the header shows the first line of the activity detail, and the expanded body (`timeline/stage.ts` failure cards, `src/tools/orchestration/ActorTool/UI.ts` actor cards) shows only the following diagnostic lines (provider, model, HTTP status, excerpt), plus the first line when it is too long for the header. Enforced by `tests/provider-outage.test.ts`, `tests/stage-flow.test.ts`.
