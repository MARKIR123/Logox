# Module: Terminal UI (`src/tui/`)

## 1. Scope
- **Owns**: React/Ink presentation under `src/tui/` (entrypoints `app.tsx`, `application.tsx`), terminal output coordination, timeline projection, local form editing and theme consumption. By inheritance also the slash command surface `src/commands.ts` (`commandCatalog`) and `src/commands/surfaces.ts` (`CommandSurfaces`), and the demo scene `src/demo.ts` with `src/demo/`.
- **Does not own**: Runtime execution and the store ([`src/runtime/AGENTS.md`](../runtime/AGENTS.md)); Actor profiles ([`src/actors/AGENTS.md`](../actors/AGENTS.md)); provider authentication and credential persistence ([`src/providers/AGENTS.md`](../providers/AGENTS.md)); theme palette and statusbar preference storage ([`src/config/AGENTS.md`](../config/AGENTS.md)); tool-owned UI modules ([`src/tools/AGENTS.md`](../tools/AGENTS.md)).
- **Design rationale**: [docs/UI-SPEC.md](../../docs/UI-SPEC.md); [docs/modules/README.md](../../docs/modules/README.md)

## 3. Common Changes
### Add a statusbar module
1. Add the id to `statusbarIds` and a label to `statusbarLabels` in `src/config/statusbar-preferences.ts`. New ids append disabled to saved layouts; `defaultStatusbar` enables only the first six (role, model, effort, permission, context, cache; git and cost stay off).
2. Add a `Descriptor` (`icon`, color `token`, `build`) to `registry` in `status/statusbar.ts` and give the id a place in `statusbarPriority` (narrow-width order). It is typed `Record<StatusbarId, Descriptor>`, so a missing entry fails typecheck. `build` returns whole variants from longest to shortest; never truncate text inside a variant. Add its hover detail to `status/notification-line.ts:widgetDetail` (and `widgetCommand` if a click acts).
3. If the module needs data not on `StageStatus`, extend `src/runtime/stage-status.ts` and populate it in `src/application-status.ts`. A variant list that returns `[]` hides the module (cost, cache and git do this when there is nothing to show). Anything that changes the footer without touching the store or statusbar preferences must call the application's `bumpStatus()` (`src/app/status.ts:createSessionStatus`; permission mode, git, usage restore).
- Tests: `tests/statusbar-modules.test.ts` (iterates `statusbarIds`), `tests/statusbar-customization.test.tsx`

### Add a slash command
1. Add an entry to `commandCatalog` in `src/commands.ts` (`name`, `usage`, `description`, `argument`). Completion, `/help` and the reserved-name check for custom commands all read this list.
2. Handle it in `src/app/submit.ts:createSubmit`: simple actions are an `if (text === '/name')` branch in the command dispatcher (near `/help`, `/skills`, `/reload`); tabbed pages are added to `src/application-commands.ts:createCommandTabsFor()`.
3. Report through the existing receipt or surface helpers with an explicit `presentation`; never classify text in a renderer.
- Tests: `tests/command-surfaces.test.ts`, `tests/statusbar-customization.test.tsx` (catalog and completion discoverability), `tests/slash-receipts.test.ts`

### Add a tab or page to a command surface
1. Build the `CommandTab` (`id`, `title`, `lines` or `toggles`) in `src/application-commands.ts:createCommandTabsFor()`, and extend `ApplicationCommandContext` for any new data.
2. Persist edits in `saveConfigToggles()` (same file), dispatched by tab id from the `onSaveToggles` callback in `src/commands/pages.ts:pageActions`.
3. `src/commands/surfaces.ts:CommandSurfaces.openPage()` and `panels/tabbed-page.tsx` render it with no changes; a single-tab page hides its tab bar.
- Tests: `tests/settings-interaction.test.tsx`, `tests/tabbed-page-single.test.tsx`, `tests/command-panels.test.tsx`

## 4. Hard Boundaries
- **Only `app.tsx` and `application.tsx` are root source files**: every other module sits in a responsibility directory; `components/` depends only on neutral foundations, and production never imports `previews/`. No global "utils" or "types" catch-all directories. Enforced by `tests/tui-module-layout.test.ts`, which lists every file per directory, so adding or moving a file means editing its `layout` map.
- **`app.tsx` composes and owns the state; routers and hooks own the logic**: `App` declares every `useState`/`useRef`, builds one `input/shell-context.ts:ShellContext` per render and hands it to `input/keyboard.ts:useKeyboard`, `input/mouse-router.ts:createMouseHandler` (installed in `mouseHandlerRef`) and `panels/overlay-page.tsx:overlayPage`; refs in the context are the same objects `App` holds. Hooks that register effects (`status/use-notices.ts`, `status/use-active-pills.ts`, `terminal/terminal-input.ts`) are called at the position the inline effects had, because effects run in registration order; the effects that read many pieces of state (focus reset, opened requests, stopping prune, hover reset, registered interrupt) stay in `App`. Regions of the render tree are presentational (`timeline/timeline-pane.tsx`, `input/pending-rows.tsx`, `input/composer-lines.tsx`, `interactions/question-dock.tsx`, `status/footer-bar.tsx`) and keep their position in the tree so nothing remounts. Enforced by `tests/tui-module-layout.test.ts` (file ownership only); the effect order itself is *Unenforced*.
- **Colors come from semantic palette tokens**: no color literals in UI source; theme revision invalidates App memoization, timeline projection and encoded rows. Enforced by `tests/color-literals.test.ts`, `tests/theme-colors.test.ts`.
- **/ensemble is one plan and one reducer**: `panels/ensemble-layout.ts:ensembleLayout` returns the rows and every hit region, `stepEnsemble` runs keyboard, mouse and footer-button commands; data comes pre-resolved from `src/commands/ensemble-model.ts:buildEnsemble` (roster order, per-actor tools through `ToolRegistry.resolveForActor`, MCP servers as folders, skills by scope), `/actors` no longer exists, and editing is delegated to `src/commands/editor.ts:openInEditor` (`$VISUAL`, `$EDITOR`, OS opener; never inside the TUI). Resources have no file watcher, so edits take effect after `/reload`. Enforced by `tests/ensemble-page.test.tsx`.
- **Pickers can stack and can show two-line rows**: `CommandSurfaces.openPicker(..., actions, back)` and `PageActions.onBack` make Esc go to the parent level (`CommandSurfaces.cancel()`); `PickerItem.detail` adds a muted second line (`panels/picker.tsx` pages such lists in pairs and maps clicks by row height), `PickerItem.valueTone` colours the right-hand text with the warning colour, and `CommandTab.actions` adds footer actions with a key to a page (`panels/tabbed-page.tsx`). The `/anamnesis` page is the user (`src/commands/anamnesis-page.ts`). Enforced by `tests/anamnesis-command.test.tsx`.
- **The sidebar is a small window host: a header bar of tabs over the page of the active tab, a column of the terminal plane**: `panels/sidebar-tabs.ts` is the registry (`SIDEBAR_TABS`: Team, Changes, Usage; ids in `CommandSurfaces` `SIDEBAR_TAB_IDS`) and the header bar (`tabHeader`: row 0 the tab strip with a `×` on every tab while several are open, a `+` that opens the next closed tab and the toggle icon `◨` (one cell, `TOGGLE_ICON`) as the last cell; row 1 a rule drawn heavy and in the accent colour under the active tab; hover recolours tabs, `×` (error colour), `+` and the toggle, and the wheel over the strip cycles the tabs; `HEADER_ROWS` = 2 rows, so every page gets `height - 2`). The toggle hides the sidebar (an overlay closes). While no sidebar is docked the timeline is `TOGGLE_GUTTER` (2) columns narrower and the same icon sits alone in those cells on row 0 (a one-column `PlaneSide` from `use-team-sidebar.ts:useTeamSidebar` `render`, hit-tested and hover-faded there; not drawn over the welcome splash), so a closed sidebar opens by mouse and nothing is drawn over timeline text. The gutter is also kept under the narrow overlay and the welcome splash so the width never jumps; docked, the header bar carries the icon and the sidebar's own gap replaces the gutter. Hover on the header tabs, `×`, `+`, both toggle icons and the team-stage actor cards fades over 150 ms (`panels/hover-fade.ts:FadeSet` for the plane-drawn sidebar, `useHoverFade` for a component-local control; `glowStep` easing, instant when `/settings` motion is off); timeline cards, list rows and the feed stay instant. The open tabs and the active tab are remembered as `sidebarTabs` / `sidebarActive` in `~/.logox/ui-preferences.json` through `CommandSurfaces.sidebarTabsStore` (unknown ids are dropped, an empty set becomes Team). While the sidebar has the keyboard, digits `1`-`9` pick the Nth tab and `w` closes the shown one. `/team` opens and shows the Team tab (a second `/team` on it hides the sidebar), `/sidebar [team|changes|usage] [show|hide|toggle]` does the same for any tab and, without a tab, only shows or hides. There are no split panes: several windows are several tabs. Changes (`panels/changes-model.ts:fileChanges`) is derived from the session's completed Edit and Write tool messages (no file is read; a Write's previous text comes from `src/tools/WriteTool/record.ts` while this process remembers it, else the counts are approximate): files newest first with `+added −removed`, a click or Enter opens the file's diffs as a Markdown result page. Usage lists the Director and every actor by tokens with cost from `getStatus()`, a click opens the actor's window. The list pages are pure in `panels/sidebar-pages.ts` (`ListModel`, `paintList`, `stepListKey`, `stepListMouse`: two-line items, the wheel scrolls three rows). The sidebar is the `sidebar` focus region (`input/focus-regions.ts`): its header rule and border (`SideFrame.level`, `tabHeader(…, focusLevel)`) ease over 220 ms between a dimmed (55% toward the background) and full strength through the `focus` key of `panels/hover-fade.ts:FadeSet`, also dimmed while the terminal window is unfocused; a click anywhere in the sidebar (header, rule, border, body) gives it the keyboard. Enforced by `tests/sidebar-tabs.test.tsx`. **The Team tab is the team stage, one act at a time; it is laid out once per events, acts, width and filter**: `panels/team-sidebar.ts` paints it (`paintTeam`: one `SideSegment` line per row, exactly the sidebar's width, colours only from the palette, no cell ever carries a `SideSegment.bg` so a translucent terminal background shows through) and reduces keyboard (`stepTeamKey`) and mouse (`stepTeamMouse`) to a new view plus effects; `panels/use-team-sidebar.ts:useTeamSidebar` owns the state; `panels/sidebar-frame.ts` owns the width rules and the border (`sideLine`, `toneColor`). There is no Tasks view and no `/tasks`: the Team page's own header is the act header (below the tab header bar), `‹ Act 2 of 3 · <title>  ━━━ 3/5 ›` (`team-sidebar.ts:headerChrome`; the label takes the status colour, a bar and done/total with a muted ` · 1 failed`; `‹ ›` and `[` `]` step to the previous or next act, a click on the title or `p` opens the Programme page; with no act the header says `Team · no acts yet` and still opens it). It docks at 34% of the usable width (clamped 36-56) by default, or at the width the person dragged it to (`panels/sidebar-frame.ts:sidebarWidth`, `dragWidth`: the border column (x 0, every row, the header bar included) is a resize handle in docked mode only, mouse modes 1002/1003 already report the drag; range `SIDEBAR_MIN` (36) to the smaller of 60% of the usable width and the width that leaves the timeline `TIMELINE_MIN` (60) columns plus its gap; the chosen width is stored as `sidebarWidth` in `~/.logox/ui-preferences.json` through `CommandSurfaces.sidebarWidthStore`, written when the drag ends, kept as chosen and re-clamped on every render so a smaller terminal never overwrites it; a double click on the border forgets it; while dragged, `use-team-sidebar.ts:useTeamSidebar` swallows every drag and release wherever the pointer is so the timeline starts no selection, and a timeline selection that ends over the sidebar keeps going as before) only at 110 columns or more and never squeezes the timeline below that: `Ctrl+B` or `/team` then open `panels/plan-sidebar-view.tsx:PlanOverlay` through `panels/overlay-page.tsx`. Docked, `App` lays the timeline out at `timelineWidth` (one column gap left of the sidebar) and the sidebar's lines travel in `PlaneFrame.side`: `terminal/terminal-plane.ts:TerminalPlane` pads a repainted history row to its width instead of erasing the line, paints a side line only when it changed (or after a scroll, which moves the column), and re-flushes once a second while a `SideSegment.clock` placeholder is on screen. Node ids (`1`, `1.2`) are never drawn anywhere the person looks (sidebar, pages, notices; they stay in the `Plan` tool, plan files, the change feed, headless JSON and the hub).
- **An act is one natural round of work, and the stage shows one act at a time**: `src/runtime/team-acts.ts:computeActs()` decides the acts from the team events and the Director's normal closes (`directorCloses()`): an act opens at the first dispatch (companion assignment or Automa job) after nothing was open and holds everything until it closes (interjections, questions to the person and their answers, an Esc and the resume, a discussion while work still runs, re-dispatches); it closes when a Director activity ended `completed` at or after the last dispatch AND all work dispatched in it has its report or result (background jobs keep it open, an interrupted round has no normal close); the next dispatch opens act 2, unless the Director passed `continueAct: true` on the first dispatch of its round (`Actor` and `Automa` input, recorded on the activity or the swarm, honoured only for the Director), which reopens the act that just closed. A discussion that dispatches nothing opens no act, posts between acts belong to none and show the last act at rest; the person's request before a dispatch opens its act; a session with no close records is one act. `actModel()` adds the tasks: a plan made inside an act gives it its nodes (a plan phase is a task, not an act; the act is titled by the plan, else by the Director's first assignment), delegations nobody planned are tasks too. `sceneAt()` is `stageAt()` over the current act's events only, with every card filled (`stageCards()`: the actor's task title with n/m, `waits techne` / `awaiting approval`, `done`/`failed`, `next: <task>`). `src/runtime/task-graph.ts:taskGraph()` still merges the plan and the delegation record (synthesized nodes are read-only copies for drawing; the plan, the plan files and the Director's change feed never see them). The Programme page (a click on the act title or `p`, `src/commands/plan-page.ts`) lists the acts, each with its tasks (glyph, title, owner, how long or running, `after <title>`, `⑂`, `◦N`), marks the act on stage, jumps the stage to an act heading (`CommandSurfaces.requestStageAct`), opens a task's detail (a plan node's page or the delegation page; Esc returns) and ends with the earlier plans to re-activate (`PlanBoard.adopt()`). Visibility: a plan that becomes active shows the sidebar (wide terminals, unless the person hid it), a done or abandoned plan hides it with a notice, a session without a plan never opens it by itself, the last explicit choice (`Ctrl+B`, the toggle icon, `/team [sidebar] show|hide|toggle`) wins for the session and Ctrl+B opens the sidebar even with nothing to show (an empty Team page). Focus is a fourth `focus` value `plan`: `Ctrl+B` once shows and focuses, `Tab` cycles to it, a click inside focuses, `Esc` or a click elsewhere returns to the composer, a typing key returns and is typed (except the sidebar's own keys `p`, `[`, `]`, `f`, Space, `+`, `-`), `Ctrl+B` while focused hides; the composer keeps its draft visible without a caret. The border column (x 0) is, docked, the resize handle (hover takes the accent colour); the collapse button is the header bar's toggle icon. Enforced by `tests/team-acts.test.ts`, `tests/continue-act.test.ts`, `tests/task-graph.test.ts`, `tests/team-stage-ui.test.tsx`, `tests/command-programme.test.tsx`, `tests/automa-fork.test.ts`.
- **Under the stage the sidebar keeps the team event stream as an online work group**: `/team [sidebar] [show|hide|toggle]` shows, hides or toggles the sidebar through `CommandSurfaces.requestSidebar(mode)` (`/team` opens it even when nothing has happened, `No team activity yet`). `panels/team-sidebar.ts` is pure: `buildTeamLayout()` (events + acts + panel width + member filter -> rows and the hit boxes, rebuilt only when those change, counted by `teamStats.builds`), `paintTeam()`, `stepTeamKey()` / `stepTeamMouse()` (one plan for drawing and hit-testing: the header and footer regions come from `headerChrome` / `footerChrome` / `pickerPlan`). A post is two rows (header: sender glyph and name in the actor colour, ` → @a @b`, ` · assign` or a status word in its status colour, `HH:MM` flush right; body: one faint line clipped with `…`, a `workers` post lists `◦` workers and `⑂` forks; a `waiting` post is the header alone); a narrow header drops the status word, then folds recipients to `@a +n`, then clips; no cell ever carries a background and selection, hover and focus are applied while painting, never in the layout. - **One anatomy for every tool card**: tool UIs build a `timeline/tool-card.ts:ToolView` (summary pieces after the title plus a rendered body) and call `renderToolCard`; they never draw bodies themselves. The elapsed time is faint and inline (` · 1.8s` right after the content; never mid-row or right-aligned), the far right end of a row is reserved for run state (`■ Stop` / `Stopping…` on a running tool in `tool-card.ts:CANCELLABLE_TOOLS`, today Shell, a `stop_actor` control whose `foldId` is the message id, handled by `app.tsx:stopActor` through `onCancelTool` -> `Application.cancelTool` -> `src/tools/process.ts:killActiveProcess`; nothing for finished tools), long titles clip with `…` inside the row, and a failure shows its reason once (red, no trailing `Error`; a denial keeps a leading red `Denied`). The body shows at most `TOOL_BODY_LINES` (12) rows and then exactly one `… N more lines` (`hunks` when the cut is at a hunk boundary) expander row, which is the fold `<messageId>-more` (own hover brightening and underline, click and Ctrl+N / Ctrl+O toggle it, part of the message layout cache key in `timeline/stage.ts:buildStageRows`); once expanded the body shows everything and the same row becomes `… show less` at its end (`tail` bodies (Shell) keep the toggle above the tail). The thinking body uses the same single expander, counting lines across all thoughts. Empty results draw one italic faint line, failures show the reason in the summary (red) and the full text below, links are underlined (`SceneSegment.underline` in both `app.tsx` and `terminal/terminal-plane.ts`), and a `fixed` card (an image, a CancelActor row, a browser action without a useful body) has no fold. - **Hidden tools draw nothing on success**: `src/tools/ui-registry.ts:isVisibleToolMessage` keeps a `hidden` or `silent` tool out of the projection (and so out of tool groups and blank-row accounting); a failed call is visible and renders one quiet row through `timeline/tool-ui.ts:hiddenToolUI` (red `▮`, muted label, red reason, no `Error` label). - **Workspace-relative paths**: tool titles show paths inside the cwd relative to it (`src/tools/ui-format.ts:relativeToCwd`), absolute elsewhere. Enforced by `tests/timeline-turns.test.ts`, `tests/tool-ui.test.ts`.
- **Animation safety**: backgrounds and column widths stay static, only fixed-width glyph slots animate, and optional motion never changes task state. The 200 ms pacing for up to eight frames is enforced by `tests/actor-thinking-animation.test.ts`; the 130 ms ten-dot Braille pacing is *Unenforced*.
- **Tool UI is tool-owned**: registered tool UIs own formatting; hidden tools have no visible or selectable surface; rendering never executes a tool. Enforced by `tests/tool-ui.test.ts`.
- **Expandable cards draw no `▮`**: tool groups and the "Task from" card lead with ▸/▾ via `pushOrdinaryCard({expandable: true})`; the whole title row (including the elapsed time) hovers and toggles through `:title_*` selection keys. Italic means summarised process (thinking title, group titles); individual tool rows stay upright. A group header is `<verb> N <noun>` per category (`timeline/group-row.ts:groupVerb()` picks a stable word per group id from the actor's `activity_verbs` pool, gerund while running, past when done), italic, white (`palette.fg`) while running and muted when finished. A collapsed running group shows each running tool as a `└` row (`timeline/group-row.ts:visibleRunningCalls()`, kept at least 700 ms per tool id); expanded groups show none. A running single-tool `▮` breathes between muted and the role color on the 200 ms frame rhythm. Enforced by `tests/tool-group-render.test.ts`.
- **The card subtitle is derived from events; the `⏵` line only adds to it**: `timeline/live-status.ts:liveStatus()` reads the activity's messages. Layer 1 is always present while the activity runs: the first running visible tool as its own card title (`tool-card.ts:messageCardTitle`, plus ` +N` for a batch) or the thinking state (`Thinking`, `Writing Edit(file) · 14.2k chars` while arguments stream, `Replying` once text flows). Layer 2 is the `⏵` text of the CURRENT reply (the assistant text after the latest request-opening thinking step, so the next reply without a line returns to layer 1; reasoning messages never feed it) shown as `<main> · <⏵ text> · <tool text>`, and `scene.ts:appendActorCard` (`actorSubtitle`) clips the `⏵` text first (and drops it below 8 columns) on a narrow card. The live part is drawn ONLY on a folded actor card (`stage.ts:activityLive`, `folded` argument): an open card (its tool rows are visible), the outer card of an actor's own window and the Director's speaker header never show it; the footer activity line and the actor-pill hover detail (`footer-model.ts`, summarizing actors you cannot see) keep it. A temporary state (`temporaryState()`) replaces the whole live part (and shows on any card); an ended card shows its main title only. The clock after the tool or thinking text is a fixed-width slot (`animation.ts:subtitleClock`, blank under a second) that `row-presentation.ts:decorateRow` fills from `SceneRow.animation.clockStart`, so it ticks without rebuilding rows. The stored assistant message keeps its raw `⏵` first line while the reply streams (`src/kernel/model-turn.ts` and `src/kernel/reply.ts` must not strip it from the store; renderers call `runtime/narration.ts:stripNarration`). A `⏵` line the model wrote always shows in the timeline: `timeline/stage.ts:buildStageRows` draws it as a faint italic one-line step heading (`scene.ts:createBuilder` `pushStageLine`, row id `<message>-stage`, clipped with `…`, `noSelect`) above that reply's text and tools, in the Director window and inside companion cards, from the live message and from a restored session alike (`src/app/restore.ts`). `timeline/tool-groups.ts:groupToolMessages` therefore no longer treats a `⏵`-only message as neutral: the heading ends the tool group or edit run before it. When the reply wrote no line, the runtime derives a fallback label from the reply's latest visible tool call (`live-status.ts:toolStageLabel`, each tool's own `ToolUI.stageLabel` in its `<Name>Tool/UI.ts`, else `Using <Name>`; `Reading src/a.ts`, `Running npm test`, `Dispatching 3 workers`) and shows it only in the folded card subtitle and the pill hover detail, in the model-line slot, only while nothing runs or thinks (between the tool calls of a reply; a running tool keeps its own card title, a new request's thinking state replaces it). The fallback is never a timeline row, never in the ledger `stage` field, summaries or anything a model reads. The speaker header (`describeRound`) never names it. Enforced by `tests/stage-header-activity.test.ts` (fallback label), `tests/narration.test.ts` (tolerant extraction, restore), `tests/tool-group-render.test.ts`, `tests/tool-groups.test.ts`, `tests/stage-process.test.ts`.
- **Image previews are half blocks decoded off the render path, and the lightbox is a surface**: `terminal/image-source.ts:imageState()` answers at once from a cache keyed by path, modification time and size and starts the PNG or JPEG decode in the background (`imageRevision()` is part of the message layout key and of `App`'s memo version, so a finished decode re-lays out the card; pixels are kept at 2048 px and a 192 px mip for thumbnails); `terminal/image-raster.ts` is pure geometry and area-averaging resampling behind an `ImageBackend` (half blocks today: foreground the top pixel, background the bottom, a cell is 1 by 2 square pixels), `timeline/image-thumb.ts:imageThumbnailLines` returns the rows an image Read puts in `ToolBody.head` (thumbnail of at most 36 columns, ratio clamped to [0.25, 4], top or left anchored crop, never upscaled; a loading box; a failed row with retry) as one `ToolLine.target` (hover id `<message>-image`, action `open_image`, also reached with Ctrl+N then Ctrl+O). A click runs `timeline/timeline-click.ts:activateImage`: `CommandSurfaces.openImage` publishes a `kind: 'image'` surface that `panels/overlay-page.tsx` draws with `panels/image-lightbox.tsx:ImageLightbox` (a centred card, facts in the top border, `✕` control, Fit / 100% / - / + / arrows toolbar, the original's path opening in the system viewer; Esc, `q`, the backdrop or `✕` close; wheel and +/- zoom, arrows or drag pan, `0` fit, `1` 100%); `panels/image-lightbox-view.ts:cardLayout` is the one plan for drawing and hit-testing. **Sixel is the sharp backend and half blocks stay underneath**: `terminal/image-graphics.ts:imageGraphics` is the process-wide capability and encoder service; `terminal/terminal-input.ts:useTerminalInput` probes once at startup (`terminal/image-protocol.ts:IMAGE_PROBE`: cell size `CSI 16 t`, window size `CSI 14 t`, then Primary Device Attributes as the barrier; attribute 4 means Sixel; `LOGOX_IMAGE_PROTOCOL=auto|sixel|halfblock` overrides) and the same `stdin.read` wrapper removes the replies from the key stream (`imageGraphics.feed`). With Sixel the fit math runs in real cell pixels (`imageGraphics.grid()`, 8 x 16 until measured), so 100% is one file pixel per screen pixel; encoding (`terminal/sixel.ts`: median-cut palette of at most 256 colours, banded run-length output) runs in `terminal/sixel-worker.ts` and lands in a cache that re-notifies the plane. The cells of a picture always hold half blocks (the fallback, and what Ink and the plane keep painting); `terminal/terminal-plane.ts:TerminalPlane` draws a timeline thumbnail as pixels only when every row of it is inside the history rectangle (`ToolLine.slot` / `SceneRow.image`), repaints the rows of any picture that moved, scrolled or lost a repainted row (cell text overwrites the pixels) before drawing it again, and `setOverlay()` carries the lightbox picture (drawn after Ink's write; removed, its rectangle is overwritten with real spaces in one write at once and the pending encode is cancelled). Interaction stays cheap: a zoomed, panned or scrolled picture shows half blocks (the lightbox's from the small mip) and its pixels are drawn once after about 140 ms of stillness; encodes are latest-wins per lane (`imageGraphics.encoded(spec, 'overlay')`, `cancelLane`), cover only the visible viewport at its screen pixel size (`panels/image-lightbox-view.ts:overlaySize`), and share one palette per picture built in the worker (`terminal/sixel.ts:paletteOf`). `LOGOX_IMAGE_DEBUG=1` appends timings to `<tmp>/logox-image-debug.log`. Enforced by `tests/tui-image-preview.test.ts`, `tests/tui-image-lightbox.test.tsx`, `tests/tui-image-sixel.test.ts`.
- **Two controls float over the timeline and never move a row**: `timeline/timeline-overlay.ts:overlayView` (called through `timelineView` by `app.tsx` and `timeline/use-reading.ts:useReading`, so the plane, the fallback pane and `readingRows()` all see the same rows) replaces rows of the visible slice. (2) The sticky message: `SceneRow.turnStart` marks the header of every user turn (`scene.ts:pushTurnHeader` `userTurn`: a human message, or the Director's assignment in an actor window); when the latest such header at or above the top row has its whole message above the viewport, the top row shows its rail glyph, name, one line of its text clipped with `…` and `↑ Jump`; a click anchors the message header at the top (`jump_message`). - **Exactly one region has the focus, and it is lit**: `input/focus-regions.ts:focusRegion` is the single answer (`composer`, `timeline`, `sidebar`, or `null` while a page, picker or login covers the screen; the region underneath is untouched, so it is focused again when the surface closes).
