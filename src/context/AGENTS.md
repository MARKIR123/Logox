# Module: Context Management & Compaction (`src/context/`)

## 1. Scope
- **Owns**: Context projections and compaction (`manager.ts`), round-memory schemas and index format (`round-memory.ts`, `contracts.ts`), dual watermarks and token estimation (`budget.ts`), discovery/environment continuity (`continuity.ts`, `environment.ts`), and usage metering (`usage.ts`).
- **Does not own**: Authoritative journals and sidecar files ([`src/store/journal.ts`](../store/journal.ts), see [`src/runtime/AGENTS.md`](../runtime/AGENTS.md)); the hidden `_FinishRound` tool definition ([`src/tools/AGENTS.md`](../tools/AGENTS.md)); task delivery and activity status ([`src/actors/AGENTS.md`](../actors/AGENTS.md)); prompt text ([`src/prompts/AGENTS.md`](../prompts/AGENTS.md)).
- **Design rationale**: [docs/modules/context.md](../../docs/modules/context.md)

## 3. Common Changes
### Change retention or watermarks
1. Global defaults live in `../config/config.ts:contextPolicySchema` (`keep_recent_rounds`, `keep_recent_tools`, `reserve_tokens`, `high_watermark_ratio`, `low_watermark_ratio`, `max_budget_tokens`, `target_budget_tokens`). Add new policy keys there; `parseActor()` rejects context keys not in that shape, except the retired `keep_index_lines`, `task_end_floor_ratio` and `compact_accept_ratio` (`../config/config.ts:RETIRED_CONTEXT_KEYS`), which config files and profiles may still carry and which are ignored.
2. Per-actor override: `../actors/services.ts:ActorServices.policy()` merges the actor's `context` over config (Director uses config as is). Shipped defaults are set in `../actors/builtins.ts:role()` and the fallbacks in `../actors/definitions.ts:parseActorProfile()`.
3. Threshold math is only in `budget.ts:watermarks()`; `manager.ts:prepare()` reads `policy.keep_recent_rounds` and `policy.keep_recent_tools`. Closed rounds also fold without any model call when a round starts (`manager.ts:ContextManager.roundStart()`, called through the `roundStart` hook of `../actors/ensemble.ts`, never for an aside): a companion folds every closed round at the tail unless the new task shares the root of its latest round; Logox folds to `keep_recent_rounds` when its cache has expired or the request is at half the high watermark.
- Tests: `tests/context.test.ts`, `tests/actor-context.test.ts`.

### Add a field to round memory
1. Add the argument to `../tools/protocol/_FinishRoundTool/_FinishRoundTool.ts:finishRoundSchema` and describe it in `../tools/protocol/_FinishRoundTool/prompt.ts`. Arguments are lenient: give it a token cap next to `FINISH_ROUND_SUMMARY_TOKENS` and handle it in `round-memory.ts:normalizeFinishRound()` (truncate, never reject).
2. Add the camelCase field to `round-memory.ts:roundMemorySchema` (the preprocess step still joins old records) and map it in `extractRoundMemory()`.
3. Provide the runtime value in `../store/journal.ts:Journal.finishRecord()` (`round-memory.ts:runtimeRoundSummary()`).
4. Render it in `manager.ts` only if it belongs in the index. The index has four fixed fields (`formatRoundIndex()`: `T<ordinal>|<title>|<summary>|<start>-<end>`; status is a bracket marker opening the summary), so another one changes `ROUND_SUMMARY_CONTRACT` in `../prompts/charter.ts` and every role's `src/actors/profiles/<id>/compression.md`.
- Tests: `tests/round-memory.test.ts`, `tests/finish-round.test.ts`, `tests/actor-compression-contracts.test.ts`.

### Change a role's memory focus
1. Edit `src/actors/profiles/<id>/compression.md` (the common contract stays in `../prompts/charter.ts`; focus only adds priorities).
2. Update the matching hash in `../actors/compression-migration.ts:shippedFingerprints`, otherwise installed unchanged copies are never refreshed.
- Tests: `tests/actor-compression-contracts.test.ts`.

## 4. Hard Boundaries
- **Context readings and cost are honest about their source**: `ContextManager.observe()` records the provider-reported size of each response (`estimated: false`); `restoreReading()` rebuilds a resumed window's reading as an estimate; `invalidatePrefix()` only marks readings estimated (it never clears another actor's). Prices come through the single `cost.ts:modelPrice` lookup (configured prices, else the synced model table's card in force at computation time, since usage records carry no timestamp; the unpriced hint on `/usage` only offers explicit `prices`, never an alias to a sibling model); a missing cache rate bills as input and marks the figure partial, and unpriced models show no cost. Enforced by `tests/status-data.test.ts`, `tests/status-live.test.ts`.
- **Cache writes are priced by lifetime**: `UsageRecord.cacheWrite1h` (from Anthropic `cache_creation.ephemeral_1h_input_tokens`) is billed at `cache_write_1h` (default 2x `input`), the remaining `cacheWrite` at the 5-minute `cache_write` rate. Cache keep-alive calls are recorded as category `keepalive` and listed per actor by `scripts/score-session.mjs`. Enforced by `tests/provider-cache-retention.test.ts`, `tests/session-scorer.test.ts`.
- **Raw journals are append-only**: compaction never rewrites or deletes ledger lines; references are one-based inclusive physical ranges in the authoritative ledger, not the readable mirror. Enforced by `tests/round-memory.test.ts`, `tests/context.test.ts`.
- **Request-only notes never survive compaction**: `continuity.ts:retainRuntimeContext()` skips transient context kinds (`reminder`, and the legacy `recovery`); the answered ones are filtered out of requests by `src/kernel/request.ts:prepareRequest()`. Compaction fork prefixes are built from the unfiltered ledger view. Enforced by `tests/transient-notes.test.ts`.
- **`_FinishRound` pairs vanish together** before repair, budgeting and serialization, except on an append-only protocol (`appendOnlyHistory` in `src/providers/capabilities.ts`), where removing them would invalidate replayed thinking; business tool pairs stay paired. Enforced by `tests/round-memory.test.ts`, `tests/finish-round.test.ts`.
- **Compaction resets the prompt cache, so it is rare and goes all the way down**: once over the high watermark (the larger of window minus reserve and `high_watermark_ratio` of the window), one pass reaches the low watermark: archive old tool results, fold closed rounds (all but `keep_recent_rounds`, then all if still above the low watermark; `/compact` forces the same ladder), fold pinned rounds only if still above the high watermark. A completed round whose summary the runtime wrote (`[runtime]`) folds like any other. Enforced by `tests/actor-context.test.ts`, `tests/round-folding.test.ts`.
- **Routine folds are mechanical and placed where they cost nothing**: a fold only lists round starts in the saved view (`journal.saveContext`, so it survives a restart) and sets `thinkingCut` like any compaction; it never calls the model, has no floor and no benefit gate. A companion's replacement point is the end of its history, so it is unconditional and silent; an activity that continues the root task of its latest closed round (`../actors/ensemble.ts:EnsembleRuntime.sameRootRound()`, persisted checkpoint root ids) keeps that round in full and folds nothing. Logox's check runs once per activity start (new round, or the Director continuing an open round after dispatched work), never between tool steps: cache expired (`cacheLifetimeMs()` known and now minus the `time` of its last assistant ledger entry at least that long) or the estimate at half the high watermark. An unknown lifetime counts as never expired. Enforced by `tests/round-folding.test.ts`, `tests/actor-context.test.ts`.
- **Stopped rounds are pinned**: a closed round whose record is `failed` or `cancelled` is skipped by the routine folds and by the watermark ladder until nothing else brings the request under the high watermark. It unpins when a `resumeTask` activity of the same actor completed, or its root task ended: a companion's Director round has a record in the Director ledger covering the root activity (root absent there: the root activity is terminal); Logox rounds, and companion tasks nobody dispatched, unpin when a later round completed normally. A lookup failure keeps it pinned. Enforced by `tests/round-folding.test.ts`.
- **One model-written merge**: only when the index lines themselves keep the request at or above the high watermark after everything foldable folded, the oldest lines (and any earlier overview) become one overview via `manager.ts:ContextManager.mergeMemo()` (`HISTORY_MEMO_INSTRUCTION`, input is only those lines), enough to get below the low watermark. No count of index lines triggers it. Enforced by `tests/round-folding.test.ts`, `tests/context-compaction-v2.test.ts`.
- **The progress summary is asked at the end of the real conversation** (`manager.ts:ContextManager.prepare()` builds the fork from the uncompacted request) so it reuses its cached prefix; a different summary model or a failure falls back to runtime extraction. Enforced by `tests/context-compaction-v2.test.ts`.
- **Thinking from before a compaction or fold is never sent again** (`contracts.ts:contextStateSchema`, `thinkingCut`): its signature bound the history that compaction replaced. Text and tool calls stay. Enforced by `tests/context-compaction-v2.test.ts`.
- **A superseded read is shrunk once, under a gate, and never flips back**: `supersession.ts:supersededReads()` names the older successful `Read` results of one actor that a later successful read of the same resolved path contains (a full read contains every range; a read the tool truncated covers only the lines it returned; images follow by path; a failed read yields only to a later success of the same selector; edits and writes supersede nothing). The result shows `prompts/compaction.ts:supersededReadText()`; the call, its pairing and every assistant message stay. A result is tombstoned only (a) when the cache is cold by the same test as `roundStart()` (unknown lifetime counts as never expired, so this gate stays closed), (b) when at most `manager.ts:SUPERSEDE_SUFFIX_TOKENS` estimated tokens follow it in the request, or (c) in the save of a routine fold or compaction that happens anyway. The decision is the `superseded` map (tool call id to range) of `contracts.ts:contextStateSchema`, saved with the view like `folded` and `imageCut`, only growing, so later requests and restarts keep it byte-stable. Never on an append-only protocol (`appendOnly` argument of `prepare()` / `roundStart()`). Enforced by `tests/context-supersession.test.ts`.
- **Images leave history only through saved decisions**: every image has a file path from creation (`ImageBlock.path`, `src/kernel/scratchpad.ts:saveToolImages()`); archived tool results and everything below `contextStateSchema.imageCut` show `[image: <path>]` text (`images.ts:imagesAsText()`), and `imageCut` is written in one batch when a request exceeds `ModelCapacity.maxImages` (down to half) or after `ContextManager.downgradeImages()`. Enforced by `tests/image-history.test.ts`.
- **A round is one record over a contiguous ledger range, usually one activity**, never every injected user message. A Director round stays open while its dispatched work is open: the activities that continue it carry `roundId` (the first activity's id, `../store/journal.ts:entrySchema`) on their user entry, `manager.ts:splitRounds()` merges them into one group, and `Journal.finishRecord()` writes the single record from the first entry to the last. A companion activity started by a teammate's message is no round: it extends the latest same-root record (`RoundPlacement` `absorb`, memory unchanged) or writes a short `[reply]` record. Ordinals are the next number after the highest saved one and after every round the raw ledger opened before it; a rewritten record keeps its ordinal. Enforced by `tests/round-boundaries.test.ts`, `tests/round-memory.test.ts`.
- **Missing or invalid metadata never invents verification.** Records the runtime writes open with `[interrupted]` (user or Director stop), `[failed]`, `[runtime]` (completed without a usable `_FinishRound`) or `[reply]` (teammate-started activity) and list only ledger facts (changed files, last Shell exit status, and for a completed round the opening of the delivered answer). Records saved with `outcome` / `verification` / `carryForward` still load: `round-memory.ts:roundMemorySchema` joins them into `summary` on read and never rewrites the file. Enforced by `tests/round-memory.test.ts`. Enforced by `tests/finish-round.test.ts`, `tests/round-memory.test.ts`.
- **Discovery pairs and the latest environment snapshot survive compaction**: original successful LoadTools pairs are retained, never fabricated or archived. Enforced by `tests/tool-disclosure-context.test.ts`.
- **Conversation language comes only from human-authored input** (`role: user`, `inputKind: human`); tool output, actor reports and Director briefings never set it. It rides the environment snapshot (`language`), so changes are `environment-change` deltas and actors share the session value. Enforced by `tests/conversation-language.test.ts`.
- **Budget estimates**: charge eager and actually expanded contracts once; exclude image base64 on full and incremental paths; an anchor is valid only for the same model, rules, tools and prefix. Enforced by `tests/tool-disclosure-context.test.ts`, `tests/context.test.ts`.
- **Titles and summaries skip persona micro-action lines**: a leading line wrapped in `（…）`, `(…)` or `【…】` never becomes a round title or opens a delivered report (`contracts.ts:titleLine`, `contracts.ts:stripLeadingActionLines`); `_FinishRound` title and summary overflow is truncated by estimated tokens, 30 and 200, with `…` (`budget.ts:truncateToTokens`). Enforced by `tests/context-titles.test.ts`.
- **Reports are not indexes**: task reports are separate full deliveries; round memory only stores them separately. Enforced by `tests/round-memory.test.ts`, `tests/finish-round.test.ts`.
- **One memory contract, one resident focus per role request**: Enforced by `tests/actor-compression-contracts.test.ts`.
- **Memory is historical data, not authority** to widen permissions or promote hypotheses to verified facts. *Unenforced* (prompt text only).

- **Depends on**: `src/store/journal.ts` (ledgers, sidecars, task checkpoints), `src/runtime/` (messages, context updates), `src/tools/protocol/` (`_FinishRound`), `src/tools/discovery.ts` (discovery names), `src/prompts/` (summary and memo instructions), `src/config/` (policy schema), `src/providers/cache.ts` (cache lifetime).
