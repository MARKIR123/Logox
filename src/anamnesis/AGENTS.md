# Module: Anamnesis (`src/anamnesis/`)

## 1. Scope
- **Owns**: The run lifecycle and its cards (`service.ts:Anamnesis`: a harvest per actor at the same time, one manual transcript run, no idle clock), what one run does (`runner.ts:AnamnesisRunner`), the transcript and new-material rules (`transcript.ts`), watermarks (`watermark.ts:WatermarkStore`), memory records (`memory.ts:MemoryStore`), dream operations (`operations.ts:applyOperations()`), skill operations (`skills.ts:SkillStore`), model resolution (`model.ts:resolveModel()`), the run prompts (`prompts.ts`) and the **harvest**, the only automatic work: the fork of an actor's own last request that writes the recap (Director only), the memory operations and the skill operations from one answer while its prompt cache is still warm (`harvest.ts`, run by `runner.ts:AnamnesisRunner.harvest()`, timed by `src/kernel/harvest-timing.ts:HarvestTiming` on top of `src/kernel/cache-keepalive.ts:CacheKeeper`). The idle recap and dream clocks (`recap_idle_minutes`, `dream_idle_minutes`) are retired; old config files still load, the keys are ignored.
- **Does not own**: The memory prompt section text (`../prompts/memory.ts:MEMORY_SECTION`); the wiring, switches and notice (`../app/anamnesis.ts:createAnamnesis()`); the card drawing ([`src/tui/AGENTS.md`](../tui/AGENTS.md)); the write exemption for memory folders ([`src/permissions/AGENTS.md`](../permissions/AGENTS.md)); usage metering ([`src/context/AGENTS.md`](../context/AGENTS.md)).
- **Design rationale**: [docs/USAGE.md](../../docs/USAGE.md) (Anamnesis section), [docs/modules/README.md](../../docs/modules/README.md).

## 4. Hard Boundaries
- **A run applies nothing until the model answered, and an aborted run applies nothing**: only a sent message (`service.ts:Anamnesis.foregroundSubmitted()`) aborts a run and removes its card; typing (`noteDraft`), finished tasks and a window switch never do; a close does the same. Memory writes (each atomic) and the watermark come after the answer. Enforced by `tests/anamnesis-runner.test.ts`, `tests/anamnesis.test.ts`, `tests/anamnesis-harvest.test.ts`.
- **The harvest forks the actor's own request so it reads the warm prefix; it never runs tools; nothing is applied before the answer**: `harvest.ts:harvestRequest()` keeps the last real request untouched (system, tools, thinking and cache fields, `maxTokens`, history), appends the reply the model gave and one user message (the static `prompts.ts:HARVEST_INSTRUCTIONS` variant for the parts asked for, then the data: date, working tree, memory records, the actor's skill categories and learned skills), and sends it with `purpose: 'harvest'`; tool calls in the answer are never executed and an answer that holds no readable block fails with `Anamnesis could not read the harvest answer`. Recap, memory and skills apply only after the answer arrived, through one serial queue (`runner.ts:AnamnesisRunner.harvest()`): harvests of different actors fork at the same time but never apply at the same time, an abort while waiting applies nothing. The recap watermark covers every owner; each actor's harvest moves only that actor's dream mark (`watermark.ts:WatermarkStore.merge()`), so the manual transcript dream sees only material no harvest covered. Memory goes through the dream's `operations.ts:validOperations()` unchanged. Usage is charged to the harvested actor's meter as category `harvest`. Enforced by `tests/anamnesis-harvest.test.ts`, `tests/harvest-skills.test.ts`.
- **The overview rides along and never blocks a harvest**: when `[context] cliff_compaction` is on and `context/manager.ts:ContextManager.cliffPlan()` says a fold is worthwhile (large context, closed rounds older than the recent ones, no peer work pending for that actor), a harvest that has other parts also asks for a `<compaction>` block in the same fork, with the scope and the role's memory focus in the appended data; recap, memory and skills never depend on it because they do not change the prefix. The block is read leniently (an empty or malformed one is absent), staged through `runner.ts:RunnerDeps.stageFold` after the answer and applied only by the actor's next request after the cache expired (see [`src/context/AGENTS.md`](../context/AGENTS.md)); the notice gains `compacted 52% → 21%` and `[Keep full context]`, which becomes `[Restore full context]` once applied and is replaced by a plain line when the fold was kept, dropped or restored (`/fold`, a click on the notice never stops a running harvest). With the setting off the instruction never contains the block. Enforced by `tests/cliff-compaction.test.ts`, `tests/anamnesis-harvest.test.ts`.
- **Skill operations are data, written only by the runtime**: `skills.ts:SkillStore` writes `<root>/<actor>/<category>/<name>.md` (user `~/.logox/skills`, project `<cwd>/.logox/skills`, actor one of the four built-ins or `public`) atomically; the frontmatter (`name`, `description`, `origin: learned`, `learned_at`, `learned_by`) is built by the runtime and a frontmatter in the body is stripped; at most 2 operations, body up to 8 KiB, slug names, a generic category (`learned`, `misc`, `notes`...) is refused, anything that looks like a secret is dropped; a `create` of a name that exists anywhere (built-in included) is refused, a new category needs `category_description` and is registered in `<root>/<actor>/agent.md` with the yaml document API (comments and other keys survive); `patch` replaces text that occurs exactly once and only in a skill whose frontmatter says `origin: learned`. Refusals show on the card; nothing triggers a `/reload`, so a new skill reaches prompts after the next reload or start. Enforced by `tests/harvest-skills.test.ts`.
- **Harvest only when the actor is settled and nothing waits on it**: the Director's moment is its cache cliff (`src/kernel/cache-keepalive.ts:warmDelayMs()`) while the keeper's `human` reason holds (no companion work, no approval or question pending, no other transcript run, no task in flight); with away warm-ups the keeper offers its last slot, and any early stop of the keeper (cost cap, unknown price) is offered too, in place of the ping. A companion is harvested by `src/kernel/harvest-timing.ts:HarvestTiming`'s own timer at its own cliff only when it has no open activity, no wake-up is certain (a peer wait is never harvested) and it has no pending interaction; the Director being busy does not block it. Only with something new (`runner.ts:AnamnesisRunner.harvestParts()`: each enabled part with material beyond its watermark; the dream switch gates memory and skills, the recap switch the Director's recap; both off means none). A model whose cache lifetime is unknown is harvested at an assumed 5 minutes (`providers/cache.ts:SHORT_CACHE_MS`, what keep-alive assumes), but a manual run never forks on that guess. A real request of the actor cancels its scheduled or running harvest. A manual `/anamnesis recap|dream` forks while the Director's cache is inside a known lifetime (`src/kernel/harvest-timing.ts:HarvestTiming.warm()`), otherwise reads the transcript (the transcript path exists only for manual runs). Enforced by `tests/anamnesis-harvest.test.ts`.
- **One manual run at a time, never while the foreground works**: `runNow` refuses with an error; a harvest never queues (`service.ts:Anamnesis.startHarvest()` returns nothing instead) and a Director harvest also waits for its tasks. A failed run is not retried; the material stays unreviewed for the next harvest. Enforced by `tests/anamnesis.test.ts`, `tests/anamnesis-harvest.test.ts`.
- **Watermarks live beside the journals** (`state/sessions/<sessionId>/anamnesis.json` in the project data folder, `src/config/project-data.ts:projectDataDir()`), one per kind; a restart does not review covered material and an unreadable answer does not move them. Enforced by `tests/anamnesis-runner.test.ts`.
- **Model answers are data**: at most 6 operations, invalid ones and anything that looks like a secret are dropped, a `user` record always goes to the user folder, a missing record is never deleted. Enforced by `tests/anamnesis-memory.test.ts`.
- **No silent model substitution**: a binding whose provider is gone or has no credentials fails with `Anamnesis has no usable model (<provider>/<model>). Choose one under /anamnesis.`; the id `anamnesis` is a binding key, never an actor. Enforced by `tests/anamnesis-runner.test.ts`, `tests/anamnesis-app.test.ts`.
- **The prompt section is read once per session and on `/reload`**, so records saved mid-session do not change the prompt prefix. Enforced by `tests/anamnesis-app.test.ts`.
- **`/anamnesis` is built from the existing surfaces**: rows are a picker (`current` empty, `focus` keeps the row just changed), the record list is a picker whose rows take two lines (`PickerItem.detail`), a record is a page whose tab carries `actions` (`d` and the footer) and uses the page confirmation, and Esc goes back one level through `CommandSurfaces.openPicker`'s `back` argument and `PageActions.onBack`. Opening the page is a submit, so it stops a run in flight. Enforced by `tests/anamnesis-command.test.tsx`.
- **An automatic dream with nothing to save leaves no card**; the card is placed by `createdAt`. Enforced by `tests/anamnesis.test.ts`, `tests/stage-anamnesis.test.ts`.
